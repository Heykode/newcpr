# 官方更新合并核对清单

适用于官方功能移植、修复同步和“已对齐官方”的验收。先固定官方提交，不能把
最新分支、旧参考工作树和本次发布基线混为一谈。以用户批准的功能边界为准。

## 合并前

- 记录官方提交、当前目标提交、关联 PR 和预期行为。
- 沿入口、共享 helper、执行器、交付和测试追踪调用链；不能只看 PR 改动文件。
- 对每个差异标记：原样移植、必要接入、用户排除、未完成。必要接入必须写明实际影响。
- 核对旧分支中的额外判断、兜底、错误映射和恢复逻辑；不能因为本地原来有就默认保留。
- 插件专属代码可以按批准边界排除；同文件中的原生协议规则和性能改进须单独评估。

## 同步测试与规范

- 每次更新同时核对受影响的实现、测试、夹具和规范。验收依据是用户确认的需求与本次固定官方源码；本地旧测试、旧规范不能仅凭存在时间更早就成为保留旧行为的理由。
- 测试失败先确认原因：新版实现缺陷、官方行为已变、夹具不再符合真实接口，或验证环境不足。只有确认实现缺陷才修代码；已过时的预期、计数、字段和规范应在同一提交更新。
- 对仍需保留的本地差异，记录具体需求和运行影响，证明不会抵消已批准的官方更新。不能为满足旧断言恢复旧绑定时机、插队路径或其他已被替换的行为。
- 更新断言须有官方代码或已确认业务合同依据；不以删除失败用例、放宽结果或忽略错误代替修复。保留官方正反例及关键本地回归，避免重复验证同一行为。
- 一次性合并、调试、回退和环境准备脚本不进入源码提交；删除失效或重复测试时同步清理其专属夹具。保留维护所需的差异账和验证结论，原始日志留在仓库外。

## 验证矩阵

| 边界 | 至少核对什么 |
| --- | --- |
| 请求入口 | 鉴权顺序、解压、字段缺失/null、非法输入、转换后执行参数 |
| 正常输出 | 文本、工具、结构化结果、身份、真实 usage、流式和非流式 |
| 错误来源 | 入口拒绝、上游 HTTP 错误、wire 失败、缺终态、转换失败、提交/结算失败分别验证 |
| 客户端交付 | 状态码、完整正文、允许透传的头、Retry-After、首帧、终态与 DONE 次数 |
| 等待和取消 | 准入前、首事件前、首事件后；保活不得重建任务；断开只取消并释放一次 |
| 非流式汇总 | 错误事件与最终完整结果的优先级、同一响应身份、完成项缺口/冲突 |
| 共享代码 | 原生 Responses、HTTP/WS 和其他调用方的既有行为是否被牵连 |
| 验证边界 | 源码比较、模拟协议、真实数据库、真实上游分别记录；没有执行不能写“通过” |

发现缺陷时先证明新用例在旧代码下失败，再验证修复后通过。测试预期要来自固定
官方源码或独立参考实现，不能只复述当前本地代码。修复时删除已失效的专用 helper
和错误分支，保留官方同样存在的公共规则。

## 验收与发布

- 将每个行为差异关联到来源、测试名称和结果；有未解释差异就不能声称全链路等价。
- 在用户指定环境执行相关测试、编译和检查，核对被验证文件与待发布源码一致。
- 报告完成项、保留差异、未执行验证和用户可见的兼容变化。官方通过 CI 不代替本地适配验证。
- 提交、推送、合并、标签和部署分别记录状态，按本次授权执行。

Chat 的具体来源、允许适配和已执行验证见 [Chat 对齐记录](chat-official-parity.md)。
