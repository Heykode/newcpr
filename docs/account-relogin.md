# 失效重登

## 使用流程

左侧「失效重登」是独立登录资料库。按行导入，仅支持邮箱、密码和 TOTP 2FA 密钥：

```text
test@example.invalid----example-password----JBSWY3DPEHPK3PXP
```

这里只是虚构格式示例。密码中的 `%`、空格、内部分隔符不被改写；
邮箱统一小写，2FA 支持 Base32 密钥中的空格和连字符。邮箱 OAuth 四段式和
`email|refresh_token|client_id` 均不再支持；Outlook 地址本身仍可使用 TOTP 资料。
导入会先校验整批，
重复邮箱需要明确勾选更新。一次最多 500 条、512 KiB，资料库最多 10000 条。
更新已有资料保留其自动重登开关，清空旧的待推送凭证。

- 在失效重登页单独导入的新资料默认允许自动重登，但未在池中的账号不会自动登录或自动入池。
- 登录只使用账号密码和 TOTP 动态验证码。初始 Web 登录进入邮箱验证码页面时，
  仅当该页明确提供密码登录，才沿用同一会话和出口切换一次，确认密码页后继续密码和 TOTP 验证。
  如果只提供邮箱验证或未列出可用方式，则直接提示邮箱验证。
  上游仍要求邮箱验证，或密码/TOTP 提交后追加邮箱验证时，停止并明确提示；
  不主动发送验证码请求，不连接 Microsoft 或读取邮箱。
- 手动「重登」只获取、验证、缓存新凭证，不入池。确认「推送」才入池。
- 自动恢复、账号管理菜单重登和「原工作区」模式锁定已有账号的原工作区。
  资料库手动「最高套餐」模式可以获取更高套餐；切换已有账号仍需单独确认推送目标。
- 新账号自动选择业务优先级：Enterprise、Edu、Business/Team、Pro、Plus、Go、Free。
  这只是本功能的选择策略，不是套餐能力的通用排名；未知套餐停止，并列最高等待人工选择。
  上游成员表、OAuth 令牌和 usage 验证统一识别官方套餐别名：
  `self_serve_business_prolite` / `self_serve_business_usage_based` 归为 Business，
  `ent26` / `enterprise_cbp_automation` / `enterprise_cbp_usage_based` / `hc`
  归为 Enterprise，`education` 归为 Edu，
  `prolite` 归为 Pro。别名按真实工作区 ID 去重，同一 ID 套餐冲突时停止。
  Team 授权失败绝不自动换成个人 Free。
- 新增入池复用原导入初始化（设备指纹、默认调度、出口绑定等），并在事务内拒绝
  并发出现的同邮箱或同身份账号。更新已有账号复用原凭据替换和版本比较，
  不删除重建账号，不改账号 ID、指纹、分组、调度配置、代理或历史统计。
- 删除只删除资料库记录，不删除号池账号。取消任务的迟到结果不能重新入池。

处理状态、缓存凭证状态、号池状态分开显示。「验证通过」表示取得时已完成验证且
本地有效期未到，不承诺凭证以后永不被上游撤销。「已同步」也不代表号池永久可用。
列表每 5 秒刷新，支持按账号名称/邮箱搜索；套餐、Web 会话、号池状态、出口、处理状态、自动恢复和最近操作时间由对应表头筛选，手机端提供相同筛选。
支持当前页全选、账号列拖动选择/取消和批量重登、推送、删除。

## 查看记录与立即重登

账号右侧的「最近操作」显示最近一次操作及时间，登录成功和失败都会记录。
点击操作名称或时间可查看历史，按登录授权、维护或资料变更分类；登录记录包含逐次的开始/完成时间、来源、工作区、登录结果和推送结果，支持加载更多。
登录成功但推送失败会分别显示；旧版没有保存的逐次详情不会补造。
「重登次数」仍只统计成功替换已有号池凭据的次数，不把失败尝试算进去。
历史随资料保留，更新资料不清空；删除资料时一同删除，号池成功次数不受影响。

点击资料库中的账号名可查看并复制完整邮箱、密码与 2FA 资料，或切换 JSON 视图。只有打开弹窗时才读取敏感资料，响应禁止缓存，
关闭后清空显示内容；普通列表不包含密钥、密码或 Token。

账号管理的更多菜单在 Excel 入口下方提供「立即重登」，点击即提交现有队列，
验证成功后自动推送到所选账号。仍遵守队列暂停、并发和重复任务检查，保留原账号
身份、工作区、设备及调度设置。失效重登资料库的重登按钮仍只获取凭据，需单独推送。

此版本新增 0087 数据库迁移，正式部署须使用迁移感知流程；不适用仅替换镜像的快速部署。

## 账号管理直接导入 2FA

「账号管理 → 导入账号 → OpenAI → 2FA」沿用相同逐行格式。
提交时确认本次账号设置，验证成功后自动入池，并把资料保留到失效重登库。
新账号使用本次分组、代理、调度和 Excel 设置；已有账号只更新原身份和工作区的
凭据，不覆盖其指纹、分组、代理、调度及 Excel 配置。

任务与失效重登共用队列和并发限制。选定代理也用于新账号的登录请求；
已有账号使用原代理。资料替换须明确勾选，已有活动任务或推送待核实时拒绝覆盖。
队列暂停时不能新建此类任务。工作区歧义仍等待选择，选择完成后继续原入池任务。
失败、取消、身份变化或推送结果不确定时不会假报入池成功，也不会盲目重放。
账号页显示本次任务进度；提交成功后清空输入中的敏感资料。

新账号首次登录失败后，使用「失效重登 → 自动重登设置」中的失败重试次数和间隔，
无需另设参数。次数不含首次：设置为 2 表示最多尝试 3 次，0 表示失败后不重试。
间隔以秒为单位，默认 30 秒；等待期间保留本次模板、代理和工作区选择，切页不取消任务。
明确封禁、工作区不可用、等待人工选择及推送结果不确定时不自动重放。
原默认 5 分钟在数据库升级时调整为 30 秒，其他已保存间隔换算成等长秒数；
已开始等待的任务保留原截止时间，后续失败采用新的间隔。

## 选择导出

失效重登页勾选一条或多条后，可选择「导出JSON」或「导出2FA」。
单次最多 200 条，须再次确认敏感资料导出。

- JSON 输出一个 CPR 账号包，可再次从账号管理导入。优先读取已明确关联的
  号池账号；尚未入池时仅使用已成功验证的缓存凭据。没有 JSON 则明确报错，
  不为导出自动登录；工作区不明确、关联账号删除或身份变化时不猜测目标。
- 2FA 输出一个文本文件，每行仍为邮箱、密码、TOTP 密钥。
- 导出接口需要管理员身份，响应禁止缓存；审计只记录所选 ID 和格式，
  不包含密码、TOTP 或 Token。普通列表仍不返回这些敏感值。

## 多工作区选择

只有一个最高套餐工作区时直接获取，例如一个 Business 和一个 Free 仍选择 Business。
多个工作区并列最高时显示可点击的「待选择工作区」，不再以普通重登失败进入冷却。
点击后查看本次登录发现的工作区名称、套餐和 ID；必须明确选择，不预选、不允许自由输入。
取消弹窗不改变任务。

等待状态保存在资料库，不占用登录进程或并发，也不自动重试。选择后点击「选择并继续」
进入队列，先验证按账号保存的 Web 会话；有效时复用，明确失效后重新登录，再校验所选工作区仍可访问、凭据身份及套餐一致。
Web 导航可避开明确停用的空间，但最终 OAuth 目标不会擅自回退到 Free。资料库手动获取成功后仍需确认推送；
账号管理的 2FA 导入任务保留已确认的入池意图，验证成功后自动入池。
已有账号的原位替换目标保持不变；选择工作区不等于同意切换号池账号。

资料、候选或原号池账号已经变化时拒绝旧确认，刷新后重新获取或选择。全局暂停时不能继续。
重新导入资料或重新发起获取会清除旧候选。本次选择不会修改账号的调度、指纹或分组。
原工作区自动恢复不进入此选择流程，也不能借此切换到其他空间。

数据库表结构不变，旧资料的新增字段默认为空。但旧版本不能读取新增的
`awaiting_workspace` 状态；回退前应暂停队列，并在当前版本完成或清理等待记录，
不能直接切换旧二进制后继续处理这些记录。

## 自动恢复

复用现有刷新机制的最终失效事实：只有启用的 OpenAI OAuth 账号处于 `Expired`，
且原因是 `AccessTokenExpired` 或 `CredentialExpired`，才尝试按邮箱匹配资料库。
普通 401、额度耗尽、无匹配资料或关闭自动重登不会触发新登录。

手动和自动任务共享一个并发上限（默认 1，可设 1–8），每 2 秒检查队列。
同邮箱只运行一项任务。每个目标凭据版本最多自动尝试 3 次，间隔依次
5、10、15 分钟。修改资料或手动重登可重新处理。
全局暂停取消正在登录的任务，排队项保留；恢复后继续。
修改自动重登开关或工作区同样使该资料的在途结果失效。

推送确认携带资料版本；原账号同时校验账号身份和凭据版本。
进入不可逆写入前持久化 `pushing`；若结果不确定或进程中断，转为
`uncertain`（推送待核实），不得自动重放旧结果。核查号池后重新重登获取凭证。
号池事务与资料状态事务不是一个跨模块事务，所以此处采用明确的不确定结果状态。

当前队列按 CPR 单实例运行方式实现，不支持多个 CPR 副本同时执行重登 worker。

## 运行环境

登录工作进程通过 stdin 获取资料，独立进程运行，不把密码放在命令行参数里。
使用 PATH 中的 `python3`，以及 `deploy/relogin-requirements.txt` 中固定的
`curl_cffi`、`pyotp`。Docker 的 runtime 和 runtime-prebuilt 共用安装步骤。

原生二进制部署需给 CPR 服务提供带依赖的 Python 虚拟环境，例如：

```sh
python3 -m venv /opt/cpr-relogin
/opt/cpr-relogin/bin/pip install -r deploy/relogin-requirements.txt
```

在服务启动环境的 PATH 前加入 `/opt/cpr-relogin/bin`。不要仅在交互 shell 激活后
误以为 systemd 服务也已生效。二进制自带 Python 脚本，但不自带 Python 解释器或依赖。
原生发行包没有 requirements 文件时，可安装同一组固定依赖：
`/opt/cpr-relogin/bin/pip install curl_cffi==0.15.0 pyotp==2.9.0`。
服务器需要正确时间、DNS 和出网；旧账号重登沿用其已保存的 HTTP/SOCKS 代理。
登录工作进程使用按账号隔离的网络会话，可复用该账号已验证的 Web Cookie 与登录设备标识，不复用号池的设备身份；不会修改号池的出口或 UA 配置。
已入池账号的固定 IPv6 源地址从现有出口运行态读取，并传给同一 Python 网络会话；
轮换策略在建立维护会话时复用现有选择器，后续维护复用仍有效的会话源地址。
未入池账号的 IPv6 固定绑定仍由入池事务分配，不能把导入策略等同于已经存在的固定 IP。
本地支持代码不会开启部署中已禁用的 IPv6，也不改写号池的轮换策略。

旧版已保存的邮箱资料因缺少 TOTP 密钥不可重登、推送或启用自动恢复。
列表提示重新导入有效 2FA；旧推送不确定状态仍保留，不能视为已完成或自动重放。
使用同邮箱有效 TOTP 资料并确认更新后可重新处理，也可删除旧资料。升级不批量清理数据库，
不影响已经入池的账号；旧邮箱字段不再读取，资料下次保存时不再写回。
资料明文保存在 PostgreSQL 独立表中，不放进调度凭证 JSON。API 列表与错误提示
不返回密码、2FA 密钥或 token；所有接口要求管理员权限。
数据库备份仍包含这些资料，应按账号凭据保管。TLS 校验保持开启。

## 验证范围

离线测试覆盖格式解析、工作区优先级、MFA 与授权页面推进、回调 state 校验、
身份/套餐不符、自动恢复门槛、取消与版本隔离、批量操作、并发上限以及推送不确定状态。
数据库测试使用临时 schema，测试后清理，不读取或改动现有号池。
浏览器回归使用虚构接口数据，不能替代真实账号的端到端验收。

此实现参考桌面脚本的协议步骤，不是原桌面应用运行环境的完整移植。
需要人工验证码、邮箱/手机确认、浏览器挑战或上游新增页面时会停止并提示，
不会绕过挑战，也不会伪报已获取凭证。

2026-09-15 经用户授权，用一个真实 Free 账号跑通当前 Python worker 的密码、
TOTP、OAuth 授权、token 交换及 usage 验证，成功取得 JSON。实测中修复了
成员表同工作区别名未去重，以及把认证事务 ID 误当作登录会话 ID 两个问题，
并补充离线回归测试。此结果仅覆盖该账号的登录 worker，不包含真实入池、
Team/Business、多工作区或 401 自动恢复的端到端验收，也未部署到服务器。
正式启用自动恢复前仍应完成授权测试账号的手动重登及确认推送联调。


## 账号维护页面与 Web 会话

- 桌面按账号、PLAN、登录状态、出口 IP、最近操作、自动恢复和操作排列。
  PLAN 复用账号管理徽章；筛选直接放在表头，手机用卡片和同等筛选。
  Web 会话、缓存 Codex 凭据、号池实时健康分别展示，不将「已同步」等同于当前健康。
  时间合并到最近操作；点击操作名称或时间均打开记录，并可按登录、维护、资料变更筛选。
  保留成功重登次数、重试进度与等待时间；全局任务并发位于「维护设置」。
- 出口列只读跟随账号管理中的绑定。账号出口编辑后，列表下次刷新和下一次维护均使用新配置；
  一个进行中的登录序列固定使用开始时的出口。没有池中账号时保留导入时选择的代理，
  包括旧记录取消任务或改为手动重登后。共享邮箱多个工作区且目标未定时明确显示多个出口。
  新账号推送时：模板明确配置优先；「保持原出口」沿用导入绑定；明确清除则使用部署默认出口。
  已入池账号只更新凭据，模板不覆盖其出口。单行展示最近检测 IP，未检测时显示脱敏代理地址；
  代理地址不是出口检测结果，默认出口不伪造具体 IP。不会因为代理出错自动改走直连。
- 点击账号名打开完整 `邮箱----密码----2FA`、JSON、编辑资料和历史版本。
  支持单字段复制和本地动态验证码；关闭或换账号后清理资料及计时器。
  编辑只修改本地资料，不代表上游密码或 2FA 已改变。
- 「检查 Web 会话」只验证 Web 登录；「获取新凭据」先复用有效 Web 会话，再以新的
  state、PKCE 和授权码交换 OAuth 凭据；「密码与 2FA 重登」从新的独立 Cookie 容器开始登录。
  重新授权不承诺每个 Token 字符串都不同，也不承诺撤销全部旧 Token。
  成功后仍沿用原有身份校验与明确推送合同。维护列表的「立即重登」沿用原排队入口，
  并发占满时等待空位，获取后待推送。手动获取凭据、密码与 2FA 重登、切换工作区、
  退出并重登都会清除遗留的自动入池意图，并保留导入时绑定的出口；
  账号管理菜单的「立即重登」保持原有队列和自动推送。资料编辑、设备或安全查询记录
  不覆盖待推送登录的记录；后续推送结果仍写回产生该凭据的那次授权。
- 设备面板可读取设备及会话、退出非当前设备、退出全部设备。全部退出只表示上游受理，
  上游可能延迟生效；本地清除保存的 Web 会话并暂停自动重登，主动授权/排队后恢复。
  「退出并重登」将退出结果落库后才进入原有重登队列，两个阶段各自记录。
  账号后端明确返回会话已撤销时，即使 Web 会话接口仍返回 Token，也按失效处理；
  主动授权允许重新建立一次会话，其他网络错误不会触发此回退。
- 工作区面板显示上游目录及可用性。「选择并授权」重新检查目标并获取该空间凭据，
  推送时沿用已有目标和切换确认；不会把 Web 导航空间当成号池目标。
- 安全面板可核对状态，分步停用旧 TOTP、准备新密钥、激活。
  停用后重新核对上游状态，不因受理响应缺少 `success` 字段而提前报错；
  上游明确拒绝并要求重新验证身份时，提示先强制重登后重试，不将未执行的操作
  记为结果不确定或锁住后续重登，也不自动重复提交。
  激活仍要求对应候选的明确成功响应。设备、状态检查的历史不标为「登录成功」。
  候选密钥和 enrollment session 先保存在私密资料库，激活明确成功才替换当前资料。
  超时/取消等不确定结果不自动重放。普通本地编辑保留候选与待核实状态；
  只有管理员明确勾选已核实资料后才解除，旧值和候选仍保存在受保护历史中（最多 10 份）。
- 远端自动改密尚未接入：它需要额外的官方身份验证，当前提供本地资料更新；
  遇邮箱、电话或浏览器验证时停止并提示人工完成，不伪造成功，也不自动读取邮箱。
- 继续使用现有失败重试次数、间隔及总超时；不增加独立无限巡检或多层重试。
  工作区等待释放并发；没有新增邮箱/短信输入等待进程。

Web Cookie 与维护材料同属现有 PostgreSQL 私密资料，按当前部署的数据库访问及磁盘保护管理；
不新增应用层加密声明，不进入普通列表、日志、错误正文或号池凭据 JSON。
维护接口使用管理员鉴权、资料 revision 和账号互斥；候选的持久化沿用 JSONB，无新增数据库迁移。
实际设备、退出和安全操作属于非公开上游接口，离线契约测试不能替代真实账号验收。

### 手动推送的新账号设置

未入池的账号直接使用账号管理“添加账号”的设置表单，可选账号/监测模板并编辑
名称、调度、并发、权重、分组、模型、出口及成本。模板用于预填，最终以表单为准。
默认保留导入出口；选择部署默认或指定代理后按所选设置入池。已有账号只更新凭据，
混合批次里的新账号设置仅用于新建账号。工作区摘要显示名称，展开可看完整 ID。

列表“立即重登”加入队列获取新 Codex 凭据，有效 Web 会话可复用，完成后待手动推送。
维护弹窗“获取新的 Codex 凭据”“密码与 2FA 重登”“选择并授权”也进入同一队列，
并发满时等待空位。其中“密码与 2FA 重登”仍强制重新登录，不复用旧会话。
工作区选择复用维护卡片，已读取的目录显示真实名称和套餐，不可访问项不可选择；
没有目录时保留最高套餐、原工作区两种策略。切换授权沿用原账号出口。
“退出并重登”先退出全部设备，再排队重登。取消只终止当前任务，不关闭自动重登开关；
后续仍符合自动恢复条件的账号可能再次发起任务。排队、执行、推送、维护及队列暂停时，
列表按钮显示对应状态。出口列展示名称和已有成功检测的延迟，详情可查看检测时间。
