# 失效重登

## 使用流程

左侧「失效重登」是独立登录资料库。按行导入，仅支持邮箱、密码和 TOTP 2FA 密钥：

```text
test@example.invalid----example-password----JBSWY3DPEHPK3PXP
```

这里只是虚构格式示例。密码中的 `%`、空格、内部分隔符不被改写；
邮箱统一小写，2FA 支持 Base32 密钥中的空格和连字符。邮箱 OAuth 四段式和
`email|refresh_token|client_id` 均不再支持；Outlook 地址本身仍可使用 TOTP 资料。
导入会先校验整批，
重复邮箱需要明确勾选更新。一次最多 500 条、512 KiB，资料库最多 10000 条。
更新已有资料保留其自动重登开关，清空旧的待推送凭证。

- 新资料默认允许自动重登，但未在池中的账号不会自动登录或自动入池。
- 登录只使用账号密码和 TOTP 动态验证码。上游要求邮箱验证码时停止并提示人工授权，
  不发送验证码请求，不连接 Microsoft 或读取邮箱。
- 手动「重登」只获取、验证、缓存新凭证，不入池。确认「推送」才入池。
- 已在池中的账号重登锁定其原工作区；同邮箱多工作区必须先指定工作区。
- 新账号自动选择业务优先级：Enterprise、Edu、Business/Team、Pro、Plus、Go、Free。
  这只是本功能的选择策略，不是套餐能力的通用排名；未知套餐或并列最高需指定工作区。
  上游成员表中的别名按真实工作区 ID 去重，同一 ID 套餐冲突时停止。
  Team 授权失败绝不自动换成个人 Free。
- 新增入池复用原导入初始化（设备指纹、默认调度、出口绑定等），并在事务内拒绝
  并发出现的同邮箱或同身份账号。更新已有账号复用原凭据替换和版本比较，
  不删除重建账号，不改账号 ID、指纹、分组、调度配置、代理或历史统计。
- 删除只删除资料库记录，不删除号池账号。取消任务的迟到结果不能重新入池。

处理状态、缓存凭证状态、号池状态分开显示。「验证通过」表示取得时已完成验证且
本地有效期未到，不承诺凭证以后永不被上游撤销。「已同步」也不代表号池永久可用。
列表每 5 秒刷新，可按邮箱、PLAN、处理状态、号池状态、自动重登开关筛选。
支持当前页全选、账号列拖动选择/取消和批量重登、推送、删除。

## 自动恢复

复用现有刷新机制的最终失效事实：只有启用的 OpenAI OAuth 账号处于 `Expired`，
且原因是 `AccessTokenExpired` 或 `CredentialExpired`，才尝试按邮箱匹配资料库。
普通 401、额度耗尽、无匹配资料或关闭自动重登不会触发新登录。

手动和自动任务共享一个并发上限（默认 1，可设 1–8），每 2 秒检查队列。
同邮箱只运行一项任务。每个目标凭据版本最多自动尝试 3 次，间隔依次
5、10、15 分钟。修改资料或手动重登可重新处理。
全局暂停取消正在登录的任务，排队项保留；恢复后继续。
修改自动重登开关或工作区同样使该资料的在途结果失效。

推送确认携带资料版本；原账号同时校验账号身份和凭据版本。
进入不可逆写入前持久化 `pushing`；若结果不确定或进程中断，转为
`uncertain`（推送待核实），不得自动重放旧结果。核查号池后重新重登获取凭证。
号池事务与资料状态事务不是一个跨模块事务，所以此处采用明确的不确定结果状态。

当前队列按 CPR 单实例运行方式实现，不支持多个 CPR 副本同时执行重登 worker。

## 运行环境

登录工作进程通过 stdin 获取资料，独立进程运行，不把密码放在命令行参数里。
使用 PATH 中的 `python3`，以及 `deploy/relogin-requirements.txt` 中固定的
`curl_cffi`、`pyotp`。Docker 的 runtime 和 runtime-prebuilt 共用安装步骤。

原生二进制部署需给 CPR 服务提供带依赖的 Python 虚拟环境，例如：

```sh
python3 -m venv /opt/cpr-relogin
/opt/cpr-relogin/bin/pip install -r deploy/relogin-requirements.txt
```

在服务启动环境的 PATH 前加入 `/opt/cpr-relogin/bin`。不要仅在交互 shell 激活后
误以为 systemd 服务也已生效。二进制自带 Python 脚本，但不自带 Python 解释器或依赖。
原生发行包没有 requirements 文件时，可安装同一组固定依赖：
`/opt/cpr-relogin/bin/pip install curl_cffi==0.15.0 pyotp==2.9.0`。
服务器需要正确时间、DNS 和出网；旧账号重登沿用其已保存的 HTTP/SOCKS 代理。
登录工作进程使用独立网络会话，不复用号池的设备身份；不会修改号池的出口或 UA 配置。
IPv6 源地址绑定策略不传入 Python 登录会话，因此需要强制指定 IPv6 登录出口的部署
应先暂停本功能，不能将“号池出口已配置”等同于“登录出口也已配置”。

旧版已保存的邮箱资料因缺少 TOTP 密钥不可重登、推送或启用自动恢复。
列表提示重新导入有效 2FA；旧推送不确定状态仍保留，不能视为已完成或自动重放。
使用同邮箱有效 TOTP 资料并确认更新后可重新处理，也可删除旧资料。升级不批量清理数据库，
不影响已经入池的账号；旧邮箱字段不再读取，资料下次保存时不再写回。
资料明文保存在 PostgreSQL 独立表中，不放进调度凭证 JSON。API 列表与错误提示
不返回密码、2FA 密钥或 token；所有接口要求管理员权限。
数据库备份仍包含这些资料，应按账号凭据保管。TLS 校验保持开启。

## 验证范围

离线测试覆盖格式解析、工作区优先级、MFA 与授权页面推进、回调 state 校验、
身份/套餐不符、自动恢复门槛、取消与版本隔离、批量操作、并发上限以及推送不确定状态。
数据库测试使用临时 schema，测试后清理，不读取或改动现有号池。
浏览器回归使用虚构接口数据，不能替代真实账号的端到端验收。

此实现参考桌面脚本的协议步骤，不是原桌面应用运行环境的完整移植。
需要人工验证码、邮箱/手机确认、浏览器挑战或上游新增页面时会停止并提示，
不会绕过挑战，也不会伪报已获取凭证。

2026-09-15 经用户授权，用一个真实 Free 账号跑通当前 Python worker 的密码、
TOTP、OAuth 授权、token 交换及 usage 验证，成功取得 JSON。实测中修复了
成员表同工作区别名未去重，以及把认证事务 ID 误当作登录会话 ID 两个问题，
并补充离线回归测试。此结果仅覆盖该账号的登录 worker，不包含真实入池、
Team/Business、多工作区或 401 自动恢复的端到端验收，也未部署到服务器。
正式启用自动恢复前仍应完成授权测试账号的手动重登及确认推送联调。
