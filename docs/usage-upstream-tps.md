# TPS 上游响应口径

## 来源与边界

官方固定版本：`96e8443ede051abdd8f0bac69462a7cfe2945633`。
依据为官方 `frontend/src/components/usage/shared/presenter.ts` 的
`usagePerformanceDetails` 和 Store analytics 的 throughput 样本表达式。

本次仅对齐管理端统计：列表、详情共用的性能展示、汇总、趋势、单项洞察及
首页趋势均使用输出 Token 除以同一完成响应的上游耗时（秒）。
不扣除推理时间，不用首事件、首 Token、引擎耗时或请求总耗时代替未知值。

## 必要接入差异

| 项目 | 官方 | NewCPR 接入 |
| --- | --- | --- |
| 响应耗时来源 | 同一响应的 created_at/completed_at | 已有 Provider 采集相同时间并存入 upstreamTimingMetrics.upstreamResponseMs，不修改采集 |
| 持久化读取 | 独立 upstream_response_ms 列 | 复用已有观测 JSON，列表、详情、汇总使用同一个严格数值投影；不迁移或重写历史数据 |
| 无有效样本 | 不伪造 TPS | 缺失、非法类型、非正整数及超出现有有符号毫秒范围的值保持未知；空分布为 null |
| 分位数 | 输出 Token / 上游响应毫秒 * 1000 | 一次聚合 P10/P50/P90，避免三次重复读取观测文档 |
| 其余统计 | 完整交付用量事实 | 保持本项目现有恢复记录、质量检测、预热、完整交付和历史汇总过滤合同 |

读模型沿 Store -> Admin -> API `latencyDetails.upstreamResponseMs` -> 前端传递。
列表仍只返回单个计时字段，不加载或泄漏完整观测文档。
总耗时、首响应、Token、金额、结算和账号累计消费均保持原样。

没有改动 Provider/Core、路由、重试、并发、出口、UA、数据库结构或设置默认值。
不包含 PR 584。实现验收后，用户另行授权提交、推送、合并、标记版本并
免备份直接部署；部署仍须通过完整 CI、安全扫描和镜像来源校验。
本次授权不包含真实模型账号测试。

## 验证

在批准的隔离 Linux 主机验证，不使用生产数据库或真实模型账号。
新增断言在旧实现下实际失败：前端得到 35.7 而非 50 tok/s；数据库得到
50 而非 250 tok/s。环境准备失败不计为业务反例。

隔离验证结果：

| 验证范围 | 结果 |
| --- | --- |
| 前端全量测试 | 1152 项通过 |
| 前端类型检查、构建、lint | 通过 |
| Store 观测查询，真实 PostgreSQL | 45 项通过；不含独立 backup_export 测试 |
| API 观测响应与路由 | 44 项通过 |
| Admin 观测服务 | 19 项通过 |
| 三个受影响后端包的全 target/feature Clippy | 严格警告检查通过 |
| Rust 格式检查 | 通过 |
| 待交付与已验证源码一致性 | 前后端跟踪文件及新增测试逐文件 checksum 一致 |

覆盖已有观测、历史空值、非法类型、非正整数、越界耗时、列表/详情映射、
P10/P50/P90、图表和单项指标。未知耗时不进入 TPS 分位数，但不丢弃原 Token
统计。保留既有数据库约束，没有放宽顶层观测文档的格式。

## 查询成本与未验证范围

2 万条、每条约 3 KiB 观测文档的合成查询中，重复 JSON 读取的初稿约
2976 ms，优化为共享单次提取及数组分位数聚合后约 474 ms；原总耗时标量
表达式约 3-6 ms。复用 JSON 免于迁移，但统计读取仍有额外成本。
这些是隔离环境的专项样本，不是生产容量或时延承诺，不宣称零开销。

没有执行生产压测、真实账号请求或全后端测试集；没有改动实际生成链路，
不能把 TPS 数值变化解释为模型生成提速。若后续大范围统计触及查询预算，
需单独评估官方独立计时列及历史回填，不在本次擅自加入数据库迁移。
