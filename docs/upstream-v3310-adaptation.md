## 运行边界

- 保留账号身份、代理/IPv6、UA、智能粘性、Guardian、Excel、质量检测隔离以及额度透支开关原有合同。
- 原生 HTTP 客户端使用 `redirect::Policy::none()`，Cookie 归属使用原生已解析的响应目标；没有插件改写目标，不引入 #511 为动态目标增加的响应来源/连接画像扩展。
- 异步预算只涉及下游 Key 的预算登记；账号累计消费仍走原账本。
- 待结算队列为单进程内存缓冲，不是持久队列。正常停机有界排空；强杀进程仍可能丢失未落库费用，不能宣传零丢失或跨副本共享待结算费用。
- 准入包含本进程待结算金额，且排除同一数据库快照中已经落库的请求 ID，避免双计费。

## 验证

### 验收发现的既有兼容缺口

以下不是官方 v3.31.0 新功能，而是本地起点已有的透支改动遗漏：

- 管理账号分页 SQL 使用了 `settings.codex_quota_overdraft_enabled`，但 settings CTE 未选出该字段，导致账号列表查询失败，开关关闭也不能避免 SQL 列解析错误。本轮仅补齐投影字段。
- 分组成员查询复用账号行解码器，却没有返回必需的 `codex_quota_overdraft_passed`，导致分组和监控读取失败。本轮按已有账号查询相同的配置 revision、凭据 revision 和额度周期条件补齐字段。
- 旧迁移回归未登记透支状态表和两个默认字段，私有测试架构登记遗漏了账号导出和透支测试；现保持严格断言，补齐精确期望与登记。
- 以上不改变透支开关默认值、探测流程、状态转换、账号身份或调度策略。

新增预算测试的独立连接池现保留隔离 schema；隔离 PostgreSQL/Redis 验收 URL 使用测试专用密码，以覆盖要求显式凭据的备份和 Store 初始化用例。

Provider 首轮验收还发现两项旧取消用例仍要求 Close 握手。对照官方 `5cfc6dee1`，同步其相同断言：取消活跃响应允许 EOF、Close 或明确的 `ResetWithoutClosingHandshake`，其他错误仍失败；正常关闭和物理连接/容量释放顺序的回归不放宽。
