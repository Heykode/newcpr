## 必要原生接入

- 官方 Retry-After 配置放在独立设置字段；本项目已有 `request_tuning_json`，沿用
  `RequestTuningOverrides -> runtime snapshot -> RoutingPlan -> coordinator` 链路。
  缺失/null 使用 240；显式 0 保留；0 表示拒绝正数 Retry-After，并不关闭所有重试。
  已开始请求使用冻结的策略，不被另一次设置保存中途改写。没有新增或改写 SQL 迁移。
- 上限仅约束上游 Retry-After 建议，不改账号真实冷却期限、准入排队时长、凭据恢复、
  输出提交屏障、请求取消和换号次数。已输出、发送结果不明、要求原账号及禁止换号的
  路径不能因超限而获得额外重放权限。
- 本项目只支持原生账号链路，所以请求上的搜索声明是 bool；连接上的状态仍为
  `Option<bool>`，区分仅握手和已发首帧。`generate=false` 预热算首帧。
  仅握手预连接可以直接接搜索请求；已启用搜索的连接在工具临时移除后仍可复用。
- 搜索切换复用现有关闭、连接许可及物理容量生命周期。仅有连接内增量历史时返回
  原有续接丢失信号，要求完整历史恢复；不能删除 previous_response_id 后发送不完整正文。
  账号、UA、凭据修订、出口和下游所有权仍由现有连接键与租约管理。
- 原生历史搜索补声明继续保留，因为它对应上一轮已核对的官方兼容逻辑；本次与搜索
  首帧检查共享相同声明识别器，不另建一套工具判定。
