## 使用入口和行为

- 设置中的错误保护默认关闭、无内置匹配规则。启用后按上游原始错误的
  provider/status/code/type/message 匹配，同一次失败只计一次，成功清零。
  冷却及恢复探测与额度冷却、手动暂停独立；诊断及质量检测不进入失败累计。
- 错误保护状态显示在账号列表。凭据更新、手动恢复和策略修订有栅栏，
  旧请求的迟到成功或失败不能更改新状态。关闭策略不提前清除尚未到期的既有保护，
  到期后不再要求恢复探测。
- 使用统计的性能区域增加负载视图：平均并发、峰值并发、准入等待和选号等待 P95。
  保留原调度视图的容量 P95 和覆盖率。请求明细筛选保持原位置。
  质量检测等内部请求不计业务并发。
- API Key 的使用配置包括模型目录地址和 Live 语音地址。
- Chat 默认保留现有执行器；只在协议转换层补齐缺失能力。
  上游终态只能补齐一致的内容，不会伪造成功或重复计费。
- WS 保留账号级物理连接上限、代理租约、身份和续接所有权。关闭中的物理连接仍占容量，
  直到实际释放；上游不主动发送保活 Ping，下游心跳独立管理。
  换绑清理仅适用于已登记真实生命周期的下游连接；仅携带 lane 标识的请求
  保留既有续接归属，避免提前关闭旧 UA、凭据或线程的物理连接。

若配置了 `openai.account_routing_override` 且出现密集
`turn_rate_limit_exceeded` 或输出变慢，可对照官方建议评估设为 `null`。
这是诊断建议，不能据此认定所有限流均由该配置引起；适配不改线上配置。
