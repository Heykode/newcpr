# Excel 上游

功能标识：`excel-upstream`。未来停用或单独删除时，遵循
[Excel 功能停用与移除](./excel-removal.md)，不要整次回退并恢复旧 State。

## 开关

- OpenAI OAuth 账号的更多操作菜单、编辑和批量编辑提供 Excel 入口开关。
- 默认关闭。开启后，选中的模型使用 Excel HTTP/SSE；未选中的模型和关闭开关后的请求使用原 Codex HTTP/WS。
- `responsesUpstream` 接受 `codex` 或 `excel`。导入、编辑或重新授权时省略该字段，保留已有选择。
- API Key 账号和其他 Provider 不支持 Excel 入口。旧 State 开关不自动转换为 Excel 开关。
- 系统设置中的 `excelDefaultModels` 初始为 `["gpt-5.6-sol", "gpt-6-astra"]`，可修改。
- 新账号 `excelModelsFollowGlobal=true`，默认跟随全局；选自定义后使用 `excelModels`。
  每份列表最多 64 项。省略保留，空数组表示没有文本模型走 Excel。
  旧客户端仅传 `excelModels` 时自动视为自定义；显式跟随全局不会删除已存的自定义列表。
  账号展示 `effectiveExcelModels`，全局更新只影响跟随账号的后续请求，不改在途冻结入口。
  匹配路由映射后的模型名，不绕过账号模型白黑名单。添加模型不等于已获上游授权。
- 升级保留已有账号列表并标记自定义，不猜测旧单模型列表是否为用户主动选择。
  可用批量编辑统一改为跟随全局。
- 账号模板可包含 Excel 开关和模型模式；旧模板未包含时保持不覆盖。
  普通导入默认不指定 Excel 配置；勾选指定后应用到相应 OpenAI OAuth 账号。
  重登推送的 `newAccountExcel` 只配置新账号且优先于模板；已有账号和自动重登保留
  原有 Excel 配置。既有账号可在账号编辑、批量编辑或应用模板时修改。

## 调度和续聊

保留 CPR 的选号评分、账号并发预算、粘性、凭据保护和出口配置。
每个逻辑请求在选中账号后固定入口，失败重试不得在 Codex 与 Excel 之间切换。
切换账号开关不取消已经开始的请求；新请求读取新配置。

客户端 HTTP、SSE 和 WS 均复用现有下游接口。Excel 模式的上游始终是
HTTP/SSE，不建立 Excel 上游 WS。关闭开关不会重新启用托管 State。

Excel 续聊使用隔离的 Redis 历史，绑定调用方 Key、账号、用户、工作区和模型。
`previous_response_id` 表示增量输入。完整历史请求则不带该字段。
父记录必须在 CPR 的交付索引中存在；未知、已淘汰或不匹配的历史明确失败，
不删除父 ID 后悄悄作为新会话生成。

历史属于敏感对话数据，不是普通日志。保留时间为一小时，不因读取延长；
单记录最多 8 MiB，整个命名空间最多 2048 条、128 MiB。容量淘汰会使对应续聊失效。
Redis 不可用时不能宣称续聊已保存。

## 协议边界

以 `Kaixxrua/excel-codex-bridge` 的 v0.4.6、
提交 `66c41df941fb1a963801964c75ff24b4a19e93f2` 为协议参考，许可证为 Unlicense。

- 转换 Excel 正文、请求头、工具目录和工具回传；只转发客户端声明的工具。
- CPR 不执行客户端 shell 或 Office 工具。原始工具身份保存在隔离历史中。
- 只接受真实完成事件。断流、失败和不完整响应不能合成成功。
- 用户消息中的内联图片先上传为附件，再带文件 ID 发起生成；已配置
  HTTPS 中转时则使用中转 URL。其他内联位置仅在明确图片错误码时上传回退。
  上传沿用同一账号、身份和出口，不允许失败后丢图继续生成。
- Excel 采用 Bearer 鉴权，不混用 Codex Cookie、托管 State 或模型 ETag。
- 日志的上游传输显示为 `Excel SSE`，下游传输仍独立记录。

与参考实现的有意差异：不静默降低未知 effort，不采用全局 call ID 缓存，
不伪造完成，不丢弃无法恢复的历史或图片；元数据使用确定性的 UUIDv8。
附件去重仅在单次请求内生效。

实际推理等级仅有 low、medium、high、xhigh；`max`/`ultra` 明确映射到
`xhigh`，`none`/`minimal` 映射到 low。诊断记录请求与实际等级，响应返回实际等级。
未知 effort、强制工具选择和 `generate:false` 预热仍明确报错。
自动模式下，已知内置工具声明被过滤并添加能力不可用说明，不会实际执行这些工具。
以上处理不回退 Codex，也不把不支持的能力伪装成成功。
上游的模型授权仍以实际响应为准，目录展示不是权限证明。

## 兼容补齐

进一步对照 `ranxi2001/sub2api` v2.8.12 提交
`ae4bc4dcbb5a3014ed3269e9f726ad70111912bf`：

- 兼容工具 JSON 围栏、别名、有限嵌套、custom 原文、命名空间及 `additional_tools`。
  不猜缺失参数，不执行 OfficeJS；重复调用身份、未知工具及终止时缺失工具均拒绝。
- 接受单个完整工具 JSON 前后的短说明及目录内的 `name(JSON)` 包装；
  函数的 JSON 必须是参数对象，custom 必须是字符串。调用名决定工具，
  参数中的 name/arguments 是普通字段。多个候选、未知名称及可执行语句仍拒绝。
- `parallel_tool_calls` 默认允许并行；显式 false 时提示单调用并校验最终数量。
  上游违规返回多个调用时整体报错，不像 Bridge 那样静默只保留第一项。
  连续并行工具结果只增加一轮 `agent_iteration`，输出位置和调用 ID 保留。
- 完整调用历史在回放缓存缺失时可重建；只有工具结果而没有调用与缓存仍拒绝。
- `text.format` 支持 `json_object` 和 JSON Schema 2020-12 的提示约束与本地校验，
  禁止外部网络或文件 schema 引用。不是原生受约束解码。
  结构化文本通过终止校验后才交付，普通文本继续增量输出。
- Excel `workspace_not_allowed` 与 `basispoints_model_access_changed` 是权限/模型拒绝，
  不因其 HTTP 429 状态误判为普通限流，不撤销整个账号凭据。真正限流及凭据错误保留原处理。
- 显式 `/v1/responses/compact` 通过 Excel HTTP/SSE 发送 `compaction_trigger`，
  只有真实完成并包含非空加密 compaction 项才成功；Codex compact 保持原流程。
- 图片附件回退仅匹配明确的图片 URL 拒绝码，不对任意 400/422 重放请求。

### 可选 HTTP 403 自动关闭（#84）

账号编辑、批量编辑、账号模板和新账号导入支持 `excelAutoDisableOn403`，默认关闭。
仅 Excel Responses/compact 的真实上游 HTTP 403 触发，
`basispoints_model_access_changed`、HTTP 200 中的 SSE 错误、连接错误及其他状态不触发。
只关闭该账号 Excel 入口；保留凭据、账号状态、调度开关、模型范围和其他设置。
当前请求保留原始 HTTP 错误，不切协议重发；后续新请求走关闭 Excel 后的既有路由。
持久化检查账号类型、凭据版本和两个开关，旧请求不得覆盖新凭据或管理员撤销的选项。
并发重复拒绝只更新一次账号和配置版本。写入有两秒截止，失败不替换原错误；
客户端取消不取消已经开始的有界写入。自动关闭保留此选项，手动关闭 Excel 并保存清除它。

### 缓存写入计量

账号编辑、独立批量选项、导入和模板中的“缓存写入按普通输入计量”默认关闭。
打开后，只对选中的 Excel 模型请求生效，关闭 Excel 入口同时清除该选项。
重登和导入省略字段时保留原配置，不改变凭据版本或身份。

例如总输入 1000、缓存读取 100、缓存写入 200：关闭时普通输入为 700，
缓存写入为 200；开启时普通输入为 900，缓存写入为 0。总输入始终是 1000，
缓存读取和输出不变，不把写入量额外加到总输入或输出。
CPR 账务和下游 `usage` 使用同一归一化结果，包括 SSE 和 compact；
经现有下游协议转交的 WS 同样消费该结果。上游原始数值保留在请求观测的
`excelBilling.upstreamUsage`，只保存固定计量字段，不保存任意上游内容。

已被旧版本误标为密文的子代理会话无法靠加标记追溯修复，需要新建会话验证。
通用 `422: Invalid request body.`、断流或无效事件流必须保留实际错误，
不能仅凭错误名称归因，也不能删除加密历史、丢图或跨后端重试掩盖。
`compaction_trigger` 始终保留为最后一项；普通 Codex 路由不受这些转换影响。

## 可选图片中转

启动配置 `openai.excel_image_relay_public_url` 缺省为 `null`，即关闭。
启用时填写指向本实例的公网 HTTPS origin，例如 `https://images.example.com`，
并转发 `/_cpr/excel-images/` 路径。不要缓存或记录此路径中的下载凭证。
负载均衡必须把图片下载发往持有该临时图片的实例；这不是跨实例共享文件仓库。

仅 Excel 的内联 PNG/JPEG/GIF/WebP 图片转为短时 capability URL。检查格式、
尺寸、像素数；单张最多 4 MiB、单请求最多 6 MiB / 16 张，单实例最多
默认 1024 MiB / 512 个图片条目、128 个持有中转图片的在途请求；容量不足明确失败，
不挤占普通文本并发。它是内存容量上限，不预分配 1 GiB；与上游磁盘缓存并非同一实现。
每个随机下载凭证最多读取 16 次，最长五分钟，请求结束或取消后立即释放。
解码前预留容量；全实例默认最多 32 个正在传输的下载。已发出的下载即使
原请求结束，也一直计入字节预算，直到 HTTP 正文及其克隆全部释放。
重试克隆共享同一生命周期；续聊重新从原始输入生成链接，不续期旧链接。
接口不接受磁盘路径，不返回目录，不使用账号 OAuth 令牌作为下载凭证。
未配置可访问的公网 HTTPS 时，不能声称已完成此功能的真实上游验收。

高级运行参数可调整图片中转总字节预算 `excelImageRelayBytes`（1–2048 MiB）、
在途请求 `excelImageRelayRequests`（1–512，默认 128）、
下载并发 `excelImageRelayDownloads`（1–128）和图片条目数
`excelImageRelayEntries`（1–4096）。调整只影响新准入，已有下载继续占用原预算；
降低预算不撤销正在传输的图片，也不重置已占用计数。
这些不是请求正文上限，不提高前述单图、单请求限制。
请求名额从内联图片准入开始，最后一个请求租约释放时归还；与下载名额独立。
旧版本已显式保存的覆盖值保持不变；没有覆盖值时使用本次代码默认值。

### 图片验收

2026-09-25 对照测试确认：直接内联返回通用 422，而同账号附件上传后
使用文件 ID 的请求成功识别颜色。因此用户消息改为上传优先，不先尝试一个
已知不兼容的请求，也不把通用 400/422 当作任意重试许可。
上传只在单请求内去重，没有跨请求的全局文件 ID 缓存。附件失败明确返回，
不会用“图片已忽略”占位文本代替图片。
可选 HTTPS 中转仍只有合成测试证据，尚未配置公网 origin 完成真实上游验收。
不把附件路径的成功当作公网中转同样成功。

### 对话图片工具

Excel 对话不执行内置 `image_generation` 工具：自动模式仅过滤该声明并提示
能力不可用，强制指定仍返回错误。
Bridge 的对话生图是客户端 `image_gen.imagegen` 工具另外发出图片请求，
不是 Responses 上游自动执行内置生图。本实现复用 CPR 已有
`/v1/images/generations` 和 `/v1/images/edits`，不创建新下游协议或模型目录。
客户端需要本身支持此工具流程；CPR 不通过伪造身份请求头强行启用客户端工具。

图片工具请求沿用 CPR 的 Key 权限、账号租约、会话粘性、出口及取消生命周期。
选中账号的 Excel 开关控制其图片后端；图片请求独立于文本 `excelModels`
列表，因为客户端工具使用的图片模型固定为 `gpt-image-2`。
开关关闭仍走原 Codex 图片接口；同一逻辑请求的重试不跨两种后端。
没有 session/thread 信息的独立请求仍按原规则选号，不宣称能绑定某个文本会话。

Excel 生成使用 JSON，编辑把 data URL 转为 multipart；只支持参考项目的
PNG、尺寸/质量选项、不透明背景、每次 1 至 3 张输出。编辑输入只接受
内联图片，不主动下载客户端给出的任意 URL，不静默丢弃图片或 mask。
鉴权、模型和工作区拒绝保留原始错误；不改用 Codex 兜底。
图片响应沿用 `http_json` 日志传输类型，诊断交换名为 `excel_http_json`，
不把非流式图片标为 SSE。仅正文 Responses 使用 `excel_http_sse`。

本轮真实测试通过客户端工具调用、图片生成、工具结果回传和图片编辑，
生成及编辑均返回 1024×1024 PNG。该证据是模拟客户端的完整工具协议流程，
不是所有客户端 UI 都已经自动启用图片工具的证明。

### 长上下文

成功完成的 Excel 响应包含非空加密 compaction 项时，续聊缓存裁剪到最新
压缩项，保留系统/开发者指令、工具目录和压缩项之后的内容。
未完成工具链或跨压缩项引用的调用不裁剪，避免切断工具配对。
同步清理窗口内不再需要的工具映射；Key/账号/模型作用域、会话编号及 TTL 不变。
不裁剪客户端提交的显式 compact 结果，不因普通失败、超长或通用 403 自动重发。

显式压缩和自动压缩均已完成真实续聊验收：使用 4096 阈值和超过该阈值的
测试上下文触发上游压缩，裁剪后仍能回忆压缩前的信息。这不等于最大上下文压力测试通过。
单记录仍受条目数和字节上限约束。默认 `compact_threshold: 200000` 是请求参数，
不是已验证的模型上下文容量保证。长上下文边界和压力测试未完成。
不能单凭 HTTP 403 判断上下文溢出，须保留并检查实际错误码和错误正文。

## 旧 State 和升级

托管 State 的后台采集、主备刷新、注入、调度门槛、WS 版本约束和前端操作已退出。
