# WS 1009 恢复与设置对照

## 基线与边界

- 官方源码固定为 `12771aca8719ed4b23b0362b23d8d81f228190ca`。
- 本次目标基线为 NewCPR `45f6f63cd`；运行环境只读核对的是 v3.33.0。
- 仅移植 1009 消息大小错误的有界同账号恢复，不整体放宽其他
  `Sent` / `Ambiguous` 错误的重放权限。不导入插件、PRISM 或隐私过滤。
- 没有更新生产设置、执行迁移、重启服务或部署；管理员已保存的覆盖值保持不变。

## 调用链与差异清单

| 位置 | 官方依据 | NewCPR 适配 |
| --- | --- | --- |
| `provider/failure.rs` 传输错误分类 | 1009 为 `MessageTooBig`，不排除在 WS 恢复外 | 增加独立分类，保留原始关闭原因和客户端 413 |
| 同文件 `apply_websocket_recovery_policy` | 1009 不增加会话失败预算；有效输出前按次数重试，然后允许 HTTP | 仅对 1009 放行发送状态不明的同账号传输恢复；保留动态次数和 HTTP 开关 |
| `gateway-core/engine/coordinator.rs` | 消费 Provider 的同账号重试、回退指令 | 核心同样放行 1009 指令；不改发送事实、不授权换号 |
| Core 错误及 API 投影 | 消息过大独立分类、最终 413 | 同步类型与协议投影；不根据错误字符串匹配重试 |
| Provider `execution.rs` | 开始执行和流中错误都走恢复策略 | 检查两条调用路径，保留输出水位、取消、账号租约和精确续接限制 |
| `transport/client_sse.rs` | 官方在 Provider 层以 15 MiB 提前分流 | 保留本地已有最终 WS 序列化大小判断、可配置阈值和开关，不复制第二套阈值 |
| `session_transport.rs` | 真正故障回退会记忆 HTTP；闲置八小时过期 | 保留现有实现；单纯超大请求提前选 HTTP 不写入该故障记忆 |

已输出文本、工具等有效内容后不能重放。精确 WS 续接仍不能换成缺历史的 HTTP
新请求。无恢复指令、取消、显式禁止重试均不能靠 `MessageTooBig` 分类绕过限制。
重试不是上游未执行的证明，不改写 `Ambiguous` 或 `replay_is_safe`。
HTTP 回退继续使用原账号身份、出口、请求投影和结算路径，不新增身份生成逻辑。

普通 SSE 入口转 WS 的 `NewChain` 可在预算用尽后回退 HTTP；下游原生 WS 的
`WebSocketNewChain` 需要建立连接续接状态，官方也不允许故障后回退 HTTP。
后者只能在允许的范围内重试 WS，预算用尽返回错误；精确续接不授权这种重放。

“默认值不同”不代表管理员配置错误，也不授权重置配置。

| 多页面保存设置的冲突保护 | 无客户端期望版本校验 | 官方提交 `configRevision`，事务内校验 `expected_revision` | 存在旧页面覆盖新设置风险，建议单独适配 |

还有一项代码差异：官方对其他未交付有效内容的 WS 发送结果不明错误也允许尽力恢复；
本次没有顺带放宽。扩大到所有断流需要另外验证工具执行和重复请求边界。

需要单独评估的本地开关边界：`provider/mod.rs` 使用会话 HTTP 记忆时未检查
`websocket_http_fallback_enabled`。因此关闭开关后，已有 HTTP 记忆的会话不会立即
切回 WS；新会话不受该旧记忆影响。官方没有相同管理员开关，不应把这一行为说成
与官方开关等价。本次只记录、不在审查其他设置时顺带修改调度。

设置保存冲突的依据：官方 `gateway-store/postgres/control_plane.rs` 在事务内先锁定
当前 revision，拒绝版本不一致的替换；官方前端提交读取时的 revision。本地
`RuntimeSettingsUpdate` 没有期望版本，保存虽然有行锁并增加 revision，但行锁不能
识别用户表单已过期。两个页面先后保存可用旧表单覆盖前一个页面的值。该项为代码
确认的风险，未在生产制造并发保存；需要完整适配前端、API、事务与冲突提示。
