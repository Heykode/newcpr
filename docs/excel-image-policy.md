# Excel 图片限额策略与错误说明

## 范围与默认值

本功能参考 Sub2API #190（合并提交 `84bc18ff9ad1ae5026c9c626a5bbab66f7ed5090`），只在已经选择 Excel 的请求中执行。不会修改账号选择、粘性、指纹、出口配置、普通 Codex 的 HTTP/WS、压缩或上下文上限。

设置页「运行参数」的高级参数提供：

| 字段 | 默认值 | 含义 |
| --- | --- | --- |
| `excelImageLimitPolicy` | `off` | `off` 保持现有图片处理；`auto_compact` 真实压缩旧图片历史；`warn` 接近上限时提醒 |
| `excelImageWarningRemaining` | `8` | 首次预警的剩余图片槽位 |
| `excelImageCompactReserve` | `3` | 预留给手动压缩的图片槽位 |

策略不会自动增大现有单张、合计字节或图片数量配置。旧版后台省略以上三个新字段时保留已保存值；显式设为 `off` 关闭策略。启用自动压缩会额外消耗一次真实上游请求及其用量。

## 具体行为

- 上限为 20、预警余量为 8、预留为 3 时：11 张正常；12–17 张首次预警，直接重试可继续；18–20 张要求先手动 compact。手动 compact 仍不能突破硬上限。
- 自动模式下，旧历史 19 张、本次新增 2 张：先真实压缩旧段，再携带压缩窗口和完整新增输入生成。不会删掉新增图片，不会拆散工具调用与结果批次。
- 本次新增已经超过上限、旧段本身超过上限、边界不明确、客户端不兼容、会话状态不可用时明确失败，不伪造摘要、不退回原生 Codex。
- 每个请求最多进行一次图片策略压缩。两阶段使用同一固定账号、模型、客户端身份及出口，不在阶段之间切换动态代理节点。原有普通请求的代理重试规则不变。
- 压缩窗口必须来自成功的上游 compaction；在交付前用 CAS 保存摘要检查点。客户端下轮回传窗口需要匹配摘要，不能任意信任或删除旧历史。
- 只在独立 Redis 命名空间保存摘要、位置和预警标记，不保存正文、图片或密文。按账号身份、Key、模型、线程和策略参数隔离，空闲两小时过期，每个会话最多 16 个检查点。
- 压缩与生成用量合并；失败保留已经报告的用量；取消不启动后台续跑。未完成的流不会伪装成成功完成。

### 与参考项目的适配差异

参考项目的策略计数仅计算 inline data URL。CPR 现有硬上限对所有 `input_image` 引用计数，本实现延续该口径，避免同一请求在策略层通过却在现有图片校验层失败。策略关闭时仍使用原有上传去重字节预算；策略开启时额外核算原始历史中的每次 inline 图片出现，避免检查点或重复图片绕过原始请求字节保护。

## 图片错误拆分

保留既有 HTTP 400 / `excel_image_input_invalid` 分类，具体消息区分：图片数量、单张编码/解码字节、合计字节、空图片、错误 data URL、Base64、非法图片数据、MIME 不匹配、尺寸和像素上限。不输出图片正文、链接、file_id 或凭据；格式错误携带 `input[i].content[j]` / `input[i].output[j]` 位置，整体预算错误指向 `input`。

`excel_image_compact_recommended` 表示预警；`excel_image_limit_reached` / `excel_image_batch_too_large` 表示不能继续新增；状态不可用与并发冲突分别使用 503 / 409。坏图片数据不会因自动压缩变成有效图片。历史生产的笼统错误没有原始请求证据时，不能全部归因为超过图片数量。

## 发布前验证

本地合成回归覆盖开关默认值、预警边界、并发 CAS、窗口校验、新增与工具批次保留、真实两阶段模拟、失败计量、取消及原生 Codex 隔离。Redis/PostgreSQL 测试需要显式配置隔离测试服务，缺少环境时会跳过，不能把测试进程成功视为数据库验收。真实上游验收只允许在授权的 OVH 测试环境进行。本次不修改生产、不提交、不推送、不部署。
