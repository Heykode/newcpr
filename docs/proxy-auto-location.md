# 代理自动出口地区

## 使用规则

- 每个已保存代理新增“自动出口地区”开关，默认关闭，已有代理不自动开启。
- 仍受设置中的“OpenAI 搜索地区与时区覆盖”总开关控制。总开关关闭时，
  不会向推理请求应用代理地区。
- 开启自动地区、修改启用自动地区的代理连接地址、手动测试已启用的代理时，
  查询出口 IP 对应的位置。普通改名不查询，不定时查询，不在推理链路查询。
- 手填地区独立保存。关闭自动地区后恢复手填值；没有手填值则继承全局配置。
- 自动模式没有可用结果时不冒充已识别，不借用原来手填的代理位置；
  请求层仍按原有规则继承全局或启动配置。
- 编辑时若连接地址留空、只修改自动地区开关，须先保存再测试；
  填入完整连接地址后，未保存的测试按当前草稿开关执行且不写入代理记录。

## 检测与失败

查询使用该代理及现有自定义 CA 信任配置，不因代理失败改走直连。
地区查询使用先前测到的具体 IP，避免两次“查询本机 IP”得到不同出口。
仅接受与该 IP 一致的完整国家、地区、城市及有效 IANA 时区。

| 结果 | 处理 |
| --- | --- |
| 完整有效的位置 | 原子保存自动位置和测试结果 |
| 连通性失败 | 显示失败，保留已有自动结果 |
| 地区查询失败，测到的出口未改变 | 显示失败，保留已有自动结果 |
| 某一 IP 族暂时测不到，其他测得地址与旧值一致且地区查询失败 | 保留旧结果及其原检测时间，不冒充最新检测成功 |
| 地区查询失败，但已知出口改变 | 清除旧自动位置 |
| IPv4、IPv6 出口时区不同 | 显示冲突，清除旧自动位置 |
| 测试期间代理被修改 | 拒绝过期结果，不覆盖新配置 |

双栈时分别查询两个出口；任意一侧查询失败不会伪装为双栈验证成功。
相同时区下选用 IPv4 的城市资料；只有 IPv6 可用时采用 IPv6。
代理连通耗时与地区查询结果分开显示。

## 数据与边界

新增迁移 `0038_proxy_auto_location.sql`，不改动历史迁移。
自动开关、手动值、检测值和最新检测结果由代理目录保存。
位置变化通过现有配置发布流程生效，不改写账号 Token、设备档案、权重、
并发限制、Cookie、State、线程编号或缓存身份种子。

地区服务是 `ipwho.is`，仅在管理员主动触发上述动作时接收出口 IP 查询。
有连接、总耗时和响应体大小限制；不跟随重定向，不公开代理认证信息。
该功能不是 IP 定位精度、上游信任或账号风控结果的保证。
