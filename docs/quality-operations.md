# 账号定时质量检测

质量运维用于定时向指定账号发送题目，并由独立账号比较实际答案与参考答案。
它不自动移组、停号、恢复账号，也不管理凭据或采集 State。
单次题目结果不能证明账号或模型是否降质，应结合多次历史观察。

## 使用

左侧“质量运维”新建规则，选择被测账号，填写准确的模型 ID、题目及参考答案。
配置五段 Cron 和时区，设置每轮 1–8 次，以及判题分组、模型和提示词。
每账号最多一条规则。规则启用后由后台执行，关闭浏览器不影响运行。
“立即检测”可以在规则暂停时使用，不会自动恢复定时任务。

判题分组必须有被测账号之外的可用账号。判题只比较参考答案与实际答案，
不要求判题模型重新解题，结果只接受严格的 `correct/incorrect/unknown` JSON。

## 执行边界

- 固定被测账号，失败不换号；判题最多尝试三个其他可用账号。
- 被测与判题请求通过普通 CPR Provider 执行链，保留账号自身 Excel 模型匹配、
  代理、IPv6、身份、指纹、模型权限、账号并发和可用性限制。
- 不使用绕过账号状态的“连接测试”诊断模式；不修改调度评分或用户粘性。
- 无用户 API Key、无用户会话延续和缓存键；记录独立 `account_quality_check` 请求类型。
- 检测消耗真实上游额度，正常记录账号累计费用，不计为普通客户端用量。
- 真实上游授权或额度错误仍遵守 Provider 原有错误处理，质量评分本身不修改账号。

## 结果与限制

通过、答案不符、不确定、请求错误分别记录；401、429、超时、空回答及非正常结束
不能作为答案不符的证据。被测请求出错即停止本轮余下次数。
普通单次请求最多 120 秒，单次判题阶段最多 90 秒；取消后等待请求收尾释放资源。
回答最多 64 KB，判题输入最多 64 KB，判题 JSON 最多 8 KB，说明最多 2 KB。

数据库租约限制全局同时最多两轮检测，每轮顺序执行。后台约五秒检查一次待运行任务，
没有规则时不产生上游调用。错过的周期不集中补发，从本轮结束计算下一次。
规则暂停、编辑或删除会在后台检查时取消旧任务，版本校验拒绝迟到结果。
进程意外退出的租约最多五分钟后恢复，旧轮次标记执行中断。

保存每轮配置快照与逐次回答；列表不读取回答正文，详情按需读取。
历史保留七天、每规则最多两百轮，页面显示最近一百轮。
删除规则同时删除对应历史，普通账号和请求记录不受影响。

## 实现与移除

核心文件集中在各层 `quality_ops` 模块和前端 `views/quality-ops`。
迁移 `0046_quality_ops.sql` 仅新增 `quality_rules` 和 `quality_runs`。
接口位于 `/api/admin/quality-ops/*`，全部需要管理认证且禁止缓存。
参考 Sub2API 的定时答题、独立判题与历史布局，以 CPR 现有基础设施独立实现，
不复制其 LGPL 源码。

停用时先暂停所有规则。移除功能需去掉菜单、路由、服务和后台注册，以及 Core
质量执行方法；不能删除已发布迁移或修改原连接测试语义。
