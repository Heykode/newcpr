# Mihomo 管理与账号请求代理

## 基线

CPR：`d5bdb633c72bc155ae10e76600f305fde54315d4`；分支：`codex/mihomo-managed-proxy`。
固定参考：`ranxi2001/sub2api@030c1fd776f1e4523728665c0a6127a0f4dbac33`，不代表已跟进其后所有提交。内核固定Mihomo `v1.19.31`，支持Linux amd64/arm64。

## 使用与边界

在现有代理管理提供普通代理、订阅管理、动态代理、节点管理、内核与规则五个标签。OpenAI账号导入、单改、批量编辑、模板均支持独立的账号请求出口：

| 值 | 作用 |
| --- | --- |
| `account`（默认） | 原账号代理、IPv6或默认直连策略。 |
| `mihomo` | 后台验证过的Mihomo会话节点池。 |
| `proxy_pool` | 普通代理管理中的代理构成独立后台验证池。 |

出口与Excel开关正交：关闭Excel时普通Codex HTTP/SSE、WS同样使用所选代理池；开启Excel时其HTTP/SSE也使用所选代理池。只有选择`account`才恢复原账号代理/IPv6/直连策略，保存的原配置不被清空。批量修改必须勾选，旧模板缺字段保留账号值。无合格出口返回`account_proxy_*`，不偷偷直连。不恢复旧STAT，不修改调度权重、账号并发、粘性、UA、TLS画像、计费、缓存键或原HTTP 403策略。其他Provider不接受未接入的代理池配置。

## 并发与失败

- 作用域包含账号、客户端Key和可信会话；匿名请求使用临时独立绑定。租约持续到响应结束或取消。
- 同会话在途请求存在时不换绑；无网络I/O发生在池锁内，不改变原账号调度并发。
- 连接失败、断流、5xx分别反馈，业务400/401/403/429不当成节点失败。
- Excel仅连接未建立、非超时、未上传附件且无同会话并发时，允许另一个已验证出口重试一次。普通Codex不新增出口切换重试，保留原重连/HTTP回退边界。不重放发送情况不明的请求。
- WS池键保留实际出口、账号、Key、会话和指纹隔离；连接本地续写不得跨节点偷换连接。在途握手和转发任务持有租约，取消完成后释放；归还空闲WS不占用活动出口引用。
- 资格探测分别使用Codex和Excel端点的无凭据请求，只认可结构化401鉴权响应；HTML挑战、403、429不算通过。不消耗真实账号模型额度，也不将可达性当作模型可用性证明。
- 成功终止事件交给下游前记录成功，防止下游不再读取时漏记；取消本身不是节点失败。
- 退休监听口REJECT，不改派其他节点；端口映射仅限当前进程，非永久墓碑。

## 参数与适配差异

上游既有参数：32个订阅、1000个订阅节点、进程内4096个监听身份和4096个会话；健康观察120秒、会话空闲30分钟、动态窗口20分钟；候选并发4、候选数32、单候选4秒。静态断流退避5分钟起/最高30分钟，动态30秒起/最高2分钟；短探测不缩短既有冷却。未增加用户业务请求次数上限。

Rust适配明确差异：管理变更返回202，在后台发布；前置阶段共享300秒预算，激活后完成有界回滚而不半途丢弃future。父进程管道EOF负责内核异常退出清理，使用正式Linux镜像已有`/bin/sh`，不是Go的Pdeathsig或unsafe pre_exec。诊断复用CPR自定义CA，禁用节点检查不扩大生产规则。敏感状态不回显，目录0700/文件0600。

## 存储、拆除与验收

迁移`0051_request_proxy_source.sql`增加账号来源及有效值约束；运行数据目录`mihomo/`保存内核与私有配置。健康、租约和端口为内存状态。拆除前将来源恢复`account`、排空请求并停止内核，再移除Host、路由、标签和Provider可选端口，无需重置凭据或原IPv6绑定。

测试仅在OVH独立容器、合成数据库与回环上游，不操作16核。验收记录见Trellis任务；编译、合成链路验证和真实模型请求不得相互冒充。许可出处见Host模块的`NOTICE.md`及`UPSTREAM-LICENSE`。
