# WS 建联与 TLS 默认配置对齐

## 来源与范围

官方基线为 `21d84af2d80d316867fadb79685a08f28b29c268`，本地起点为
`d5f8739d25e7a380cf42f9d3e477e90ce728fea6`。本次只对齐普通直连 WS 建联、
默认 Rustls provider 和出口文案，不移植其他调度机制，不改变依赖版本。

| 边界 | 原行为 | 最终行为与依据 |
| --- | --- | --- |
| 普通直连 WS | 全部通过账号拨号器中的 Hyper TCP connector | 与官方一致使用 `connect_async_tls_with_config`，由已固定的依赖交替尝试地址 |
| 显式代理或源地址 | 账号拨号器决定实际出口 | 保留此分支；新增直连分支必须确认没有源地址，不能绕开账号出口 |
| 环境代理 | 不继承进程环境代理 | 与官方条件一致：环境代理存在或配置无效时使用显式拨号路径，不能意外继承环境代理 |
| 连接预算与错误 | 现有预算、15 秒握手上限、类型化出口错误 | 沿用相同入口、超时和错误映射，不增加重试或发送后重放 |
| 默认 TLS provider | 改写默认 provider 为旧十项签名列表 | 与官方初始化一致，安装完整 aws-lc 默认 provider；当前十三项，宿主预装 provider 优先 |
| TLS 其他消费者 | 共用进程 provider；native HTTP 单独使用 native-tls | 明确 Rustls helper、代理及其他共用 provider 的消费者也获得默认签名；native HTTP 的 TLS 后端不变 |
| 出口文案 | `unchanged` 被称作默认 IPv4 | 改为默认直连；不绑定地址池，实际地址族取决于部署网络 |

普通直连与显式路线共用相同 WS 配置、压缩、业务头、连接池和错误处理。账号
身份、UA、HTTP/WS 请求体、租约和续接归属均不改变。普通直连仍支持双栈；
指定实例关闭 IPv6 应修改其部署网络，不能把产品代码硬编码为只支持 IPv4。

## 验证记录与保留检查

- 回归先在旧运行时代码上执行，实际 ClientHello 签名差异必须导致失败。
- 一次性 ClientHello 对比使用独立子进程，
  分别捕获真实生产 Provider 请求入口和官方默认连接器；避免进程 provider
  初始化导致参考端与被测端意外共用同一配置。
- 比较 TLS record/legacy 版本、session ID 长度、cipher suites、压缩方式和所有
  扩展的稳定内容。保留 SNI、supported_versions、签名/分组内部顺序及 key share
  类型和长度；只规范化 Rustls 随机扩展排列、随机数、session ID 和临时公钥。
- 保留宿主预装、并发初始化、合法及非法证书、TLS 密钥边界、嵌套 HTTPS 代理、
  UA 不改变 TLS、默认双栈、明确源地址不回退和代理失败不绕行的既有用例。
- 在仓库外验证 IPv6 监听不可用时通过 IPv4 完成真实 WS 回环请求，以及环境代理
  存在时默认直连不被代理截走。以上两项与一次性 ClientHello 对比不作为新增
  仓库测试保留；原有官方同类 TLS 测试仅随默认签名更新预期。
- 指定验证环境执行测试和构建；不用真实上游账号，也不以回环结果声称风控降低
  或生成速度提升。

## 部署边界

应用版本部署不自动关闭实例 IPv6；网络切换是独立的配置操作，以下为其操作边界。

关闭某实例的 IPv6 时，核对当前全局模式和账号覆盖项；只有默认直连的账号
无需调整账号记录。保留地址池、固定绑定和 Docker 网络，仅移除应用服务的
IPv6 endpoint，并停用该实例专用的地址维护服务。同步移除该部署必须成功的
IPv6 验收项，保留 IPv4 验收；配置备份与恢复信息保存在仓库外。

切换复用已验证镜像部署流程和既有优雅退出预算，不中途直接拔掉承载业务的
网络。检查健康、IPv4 连通、IPv6 路由/地址/连接及受保护服务。外部代理的最终
出口由代理管理，不因关闭本容器 IPv6 而修改远端代理设置。
