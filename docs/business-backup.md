# 业务备份与恢复

管理端 S3/R2 新备份为 gzip 压缩 SQL（`.sql.gz`）。保留完整 schema 和迁移历史，
账号凭据、设备身份、出口、分组、下游 Key、设置、模板、额度预算、累计消费与去重账本。
不包含请求明细、关联错误事件、详细错误采集任务和材料索引、管理员审计日志。
运行日志及错误采集文件不在数据库归档内。

## 历史统计

在与业务表相同的可重复读快照内，按现有完整交付口径汇总全局小时请求数、
成功/失败等结果、Token 与实际费用；内部质量检测和已恢复的中间失败沿用现有排除规则。
只包含快照时仍保留的已结束请求，不是永久累计账本；在途请求不导出。
本项目没有官方异步统计投影，导出直接汇总必要列；查询超时会明确失败，不静默丢统计。

恢复后的 `backup_usage_hours` 仅补充未筛选的全局总量和趋势，不伪造请求或账号身份。
按账号、Key、模型等筛选的历史、尝试次数、计费覆盖率、延迟分布以及小时内精度无法恢复。
不足一小时的查询按小时起点归属；短周期图将历史小时值记在对应小时起点，不能代表分钟分布。
现有在线请求继续按原精度统计，再备份会合并恢复基线和新请求，不重复累计。
历史清理仍处理真实日志，不撤销恢复的汇总基线；账号累计与去重账本独立保留。

## 离线恢复

先停止应用写入，选择空目标库，校验备份记录中的 SHA-256 及 `gzip -t`。
新归档使用与数据库匹配的 PostgreSQL 客户端：

```sh
set -o pipefail
gzip -dc backup.sql.gz | psql -X --single-transaction --set=ON_ERROR_STOP=1 \
  --password --dbname='postgresql://restore_user@127.0.0.1:5432/restore_db'
```

旧 `.dump` 归档继续用 `pg_restore`；下载文件名根据记录格式生成。
升级前尚未开始导出的旧格式任务会明确失败，需重新创建；完整旧暂存可继续恢复上传。
没有新增在线恢复 API。恢复后按原部署恢复流程核对密钥、业务数据、
非终态任务、运行文件和计划，再恢复服务。需要完整请求历史时另做整库备份。

## 资源与失败

有界流式压缩，仅暂存一份归档；大小限制和 SHA-256 都针对实际压缩字节。
快照和导出共享生命周期；取消、失败及导出期限到期会终止子进程并清理部分文件。
迁移 0076 仅增加恢复统计表，不改既有业务表和运行配置。
