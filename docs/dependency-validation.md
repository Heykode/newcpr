# 依赖升级与上游修复验证

## 范围

本轮基于 `a1ee9819`，上游参考固定为 `590c4a163bc8a41b74eb86be3e9f9845b960013b`。
采用逐项验证后再做组合回归的方式，不整体覆盖上游依赖表。
测试环境为 Linux AMD64；不能据此推定 macOS、Windows 或 ARM64 已验证。

## 业务修复

| 项目 | 原行为 | 本轮行为 | 保留边界 |
| --- | --- | --- | --- |
| 代理导入锁 | 拒绝导入时，释放锁与后续修改可能存在时序窗口 | 拒绝返回前等待共享锁释放；记录不存在时仍返回原来的未找到错误 | 不改变成功导入的预留锁生命周期 |
| 新模型透传 | 发现目录缺少模型时，路由或账号筛选可能提前拒绝 | OpenAI 发现目录不再被当作完整白名单，最终支持情况由上游判定；即时选择与容量等待使用同一规则 | 保留 Key 账号范围、模型映射、禁用 Provider、账号健康、额度、并发、粘性及续接所有权 |
| 启动诊断 | 缺少字段不易定位，退役配置可能阻止启动 | 报告缺失字段路径；仅忽略明确退役的三个字段并警告 | 不输出字段值；拼写错误、类型错误和业务无效值仍拒绝；保留有效的地区覆盖配置 |

退役字段仅包括 `openai.tls`、`openai.fingerprint`、
`host.logging.file.max_files`。这不是移除运行中的 TLS 或指纹能力。
显式历史压缩接口同样允许目录未列出的模型，仍校验请求合法性、账号范围及上游压缩结果。

## 指纹与性能边界

- 保留 UA 选择、完整 UA 发送、设备档案、会话隔离、HTTP ALPN、WS 握手参数、
  ZSTD 级别、小消息门槛、智能粘性及等待预算，未增加新的画像模式。
- 基线与 TLS 单项候选各采样四条路径，每条十次：
  原生 HTTP、上游 WebSocket、Rustls HTTPS 代理及原生 HTTPS 代理。
  对比稳定字段、扩展内容、长度和 ALPN；仅规范化 Rustls 原本随机的扩展顺序。
- `native-tls` 默认最低协议版本从 TLS 1.0 提高到 TLS 1.2；
  本次 Linux 基线实际已仅提供 TLS 1.3/1.2，采样稳定字段未发生变化。
  这不代表支持仅 TLS 1.0/1.1 的遗留代理，也不代表所有平台指纹完全相同。
- ZSTD 覆盖空正文至 1 MiB 的重复、模式及 JSON 样本。字节相同不等于已完成吞吐或延迟基准测试。
- 自动化测试及握手一致性不能证明上游风控行为不会变化，也不能保证任何环境绝无故障。
- 后端和前端依赖安全扫描在本轮执行时没有报告已知漏洞；结论不覆盖所有系统包、未来公告或未扫描平台。

## 验证结果

最终组合结果：

- 后端 2,984 项测试通过，PostgreSQL/Redis 集成测试实际执行。
  两项显式采样测试另外执行通过，不把子进程的重复输出计作新测试。
- `cargo fmt --check`、全目标全特性 Clippy 检查通过。
- 前端最终组合在本地和新 Node 26 Linux 构建镜像中均通过 325 项测试、代码检查及构建。
  发布说明清洗浏览器测试与地区设置页面多尺寸检查通过。
- 组合 TLS 采样与基线一致；另在现有运行镜像中执行四条路径采样，稳定字段也一致。
  组合 ZSTD 的 30 组样本与基线压缩字节一致。
- 19 个冻结迁移文件校验通过；发布脚本测试、工作流检查和候选内容隐私检查通过。

## 在线验证边界

- 已替换现有非生产实例的程序和网页，健康接口正常返回 `204`，
  网页入口与入口资源哈希匹配最终构建，运行版本为候选验证版本。
- 配置文件、环境变量、挂载及资源限制保持不变；持久化账号绑定、
  设备档案、UA 和业务设置的前后哈希一致。数据库、Redis 和下游网关容器未重建。
- 原实例在更新前已有上游认证失败。更新后原有启用分组没有就绪账号，
  另用临时分组进行了一次有界复测，仍触发现有凭据失效处理。
  这部分未得到成功推理结果，不能计作通过；不继续尝试剩余账号。
- 临时测试 Key、分组及管理员 API Key 状态已清理恢复，原账号分组关系前后相同。
  认证失败引起的账号凭据状态更新是实际测试结果，没有伪造恢复为正常状态。
- 下游网关现有渠道尚未确认只指向本次测试实例，因此没有通过这些渠道发送推理请求。
  后续需可用的测试凭据和明确限定到测试实例的渠道，补齐真实端到端成功验证。
- 部署脚本曾误把正常的 `204` 当作失败并回滚，旧镜像又与现有迁移集合不匹配；
  已修正探测并恢复经过回归的候选程序，未删除或修改数据库迁移记录。
  后续部署应备份实际运行二进制和网页，不能仅凭容器原始镜像标签认定可安全回滚。

## 复验方法

使用仓库固定工具链，并配置实际 PostgreSQL/Redis 测试连接：

```sh
cd backend
cargo fmt --check
cargo clippy --all-targets --all-features --locked -- -D warnings
cargo test --workspace --lib --test main --locked
cargo test --workspace --lib --test main --locked capture_tls_upgrade_matrix -- --ignored --nocapture
cargo test --workspace --lib --test main --locked capture_zstd_upgrade_corpus -- --ignored --nocapture
```

前端使用 pnpm 11.7.0：

```sh
cd frontend
pnpm install --frozen-lockfile
pnpm test
pnpm format:check
pnpm build
node tests/browser/release-notes.mjs
```

浏览器测试需要 Playwright 与 Chromium，也支持通过 `PLAYWRIGHT_MODULE`、
`CHROME_PATH` 指定已有安装。原始凭据、服务器配置、抓取结果和运维证据不进入仓库。
