# 上游功能选择性移植

本批以统一出站实现为基础，不替换账号选择、粘性评分、设备身份、UA、TLS、
Cookie 分区、HTTP/WS 压缩、续接归属或计费系统。

## 功能范围

| 参考项 | 本项目处理 | 边界 |
| --- | --- | --- |
| Key 并发排队（#104） | 在原 Redis 准入前后补有限排队、取消回收和共享等待截止时间 | 默认关闭，不代替账号忙时等待 |
| 可关闭的地区覆盖 | Web 运行参数增加默认关闭开关 | 地区值仍取原配置文件，关闭不清空 |
| IPv6 代理探测（#110） | 默认目标改为双栈 `api64.ipify.org` | 保留证书验证、显式代理、超时、大小限制及失败规则 |
| 更新路径（#111） | 更新器默认继承 API 实际解析的静态资源路径 | 显式覆盖仍支持；Docker 不因此获得在线二进制更新能力 |
| 套餐同步（#112） | 从新额度响应同步套餐，Token 刷新不覆盖已存资料 | 保留凭据版本和观察时间防旧写入，不自动创建账号身份 |
| Chat（#96） | 补用户文件输入和公开推理历史 | 不整套替换，不回放完整流式文本，不接半套旧函数协议 |
| 发布流程 | 版本与对应更新说明同一提交，增加独立配置和固定版本 compose 资产 | 不扩大当前 Linux AMD64 发布矩阵，不绕过签名或隐私检查 |

## 使用与限制

- 批量编辑保持现有“勾选哪项才改哪项”的规则。
- 地区开关位于运行参数；开启使用已有 `openai.wire_profile.location`，默认
  `US / Ohio / Piketon / America/New_York`。自定义地址仍修改原配置，
  本批没有增加 Web 地址输入框，也不根据出口 IP 自动定位。
- Key 最大等待人数填 0 关闭；填正整数开启，超时单独设置，默认 30 秒。
  请求的预算、RPM、账号范围、原有续接约束仍生效。
- 双栈目标修复“探测目标仅有 IPv4，而代理只有 IPv6 出口”的误判原因；
  不修复代理自身故障、DNS 故障、证书错误、目标不可达或上游拒绝。
- 更新器默认仓库为 `Heykode/newcpr`。静态资源先应用 `CPR_WEB_DIST_DIR`
  和相对路径解析，再交给更新器，避免服务目录与替换目录不一致或重复拼接。
- 发布前将 `release/notes.md` 第一行设为 `# v<目标版本>`，正文非空，
  保持该文件有未提交修改，其余受跟踪文件干净，再调用 `release/publish`。
  脚本会提交、打标签、推送并触发工作流；实现验证不会执行这些远程动作。

## 回退

没有新增数据库迁移。回退旧二进制前先备份运行设置，再按 API 文档移除旧版
不认识的新增字段。不要删除账号、凭据、设备档案、历史迁移或既有运行数据。
验证通过只说明覆盖场景符合预期，不代表生产环境零风险或风控效果保证。
