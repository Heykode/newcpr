# 上游功能选择性移植

本批以统一出站实现为基础，不替换账号选择、粘性评分、设备身份、UA、TLS、
Cookie 分区、HTTP/WS 压缩、续接归属或计费系统。

## 功能范围

| 参考项 | 本项目处理 | 边界 |
| --- | --- | --- |
| Key 并发排队（#104） | 在原 Redis 准入前后补有限排队、取消回收和共享等待截止时间 | 默认关闭，不代替账号忙时等待 |
| 可关闭的地区覆盖 | Web 运行参数增加默认关闭开关 | 地区值仍取原配置文件，关闭不清空 |
| IPv6 代理探测（#110） | 默认目标改为双栈 `api64.ipify.org` | 保留证书验证、显式代理、超时、大小限制及失败规则 |
| 更新路径（#111） | 更新器默认继承 API 实际解析的静态资源路径 | 显式覆盖仍支持；Docker 不因此获得在线二进制更新能力 |
| 套餐同步（#112） | 从新额度响应同步套餐，Token 刷新不覆盖已存资料 | 保留凭据版本和观察时间防旧写入，不自动创建账号身份 |
| Chat（#96） | 补用户文件输入和公开推理历史 | 不整套替换，不回放完整流式文本，不接半套旧函数协议 |
| 发布流程 | 版本与对应更新说明同一提交，增加独立配置和固定版本 compose 资产 | 不扩大当前 Linux AMD64 发布矩阵，不绕过签名或隐私检查 |

## 使用与限制

- 批量编辑保持现有“勾选哪项才改哪项”的规则。
- 地区开关位于运行参数；开启使用已有 `openai.wire_profile.location`，默认
  `US / Ohio / Piketon / America/New_York`。自定义地址仍修改原配置，
  本批没有增加 Web 地址输入框，也不根据出口 IP 自动定位。
- Key 最大等待人数填 0 关闭；填正整数开启，超时单独设置，默认 30 秒。
  请求的预算、RPM、账号范围、原有续接约束仍生效。
- 双栈目标修复“探测目标仅有 IPv4，而代理只有 IPv6 出口”的误判原因；
  不修复代理自身故障、DNS 故障、证书错误、目标不可达或上游拒绝。
- 更新器默认仓库为 `Heykode/newcpr`。静态资源先应用 `CPR_WEB_DIST_DIR`
  和相对路径解析，再交给更新器，避免服务目录与替换目录不一致或重复拼接。
- 发布前将 `release/notes.md` 第一行设为 `# v<目标版本>`，正文非空，
  保持该文件有未提交修改，其余受跟踪文件干净，再调用 `release/publish`。
  脚本会提交、打标签、推送并触发工作流；实现验证不会执行这些远程动作。

## 回退

没有新增数据库迁移。回退旧二进制前先备份运行设置，再按 API 文档移除旧版
不认识的新增字段。不要删除账号、凭据、设备档案、历史迁移或既有运行数据。
验证通过只说明覆盖场景符合预期，不代表生产环境零风险或风控效果保证。

## 后续缺口补齐

本批按实际缺口移植，不以 PR 名称判断本项目是否已有功能。

| 参考项 | 本项目处理 | 保留边界 |
| --- | --- | --- |
| 停用账号诊断（#122） | 指定诊断可单独读取被正常候选查询排除的账号 | 普通请求仍排除停用账号，不自动启用；保留各 Provider 原有诊断反馈规则 |
| WS 错误交付（#99） | 将客户端无法消费的裸错误包装成 `response.failed` | 可识别的状态错误和续接控制错误保留原样，不改变计费或内部重试 |
| 同窗口额度恢复（#95） | 同一已知窗口连续两次新鲜观测未触顶时允许恢复 | 保留原重置恢复规则、耗尽事实绑定、凭据状态与启停状态 |
| 后台导入（#119） | 服务端承接导入任务，Web 查询进度、停止未开始项 | 复用原导入事务、账号身份和设置；结果不确定的令牌交换不自动重试 |
| 用量表列显隐（#121） | 成功记录与错误排查各自保存列偏好 | 账号表已具备此功能，不替换原账号列、布局或批量编辑 |
| 下游环境请求头（#117，选择性参考） | 补 SDK、浏览器环境头过滤及会话别名规范化，并对齐最终版的四项扩展头透传 | 不接入上游 PR 的整体模块重组，不修改原 UA、TLS、正文或生成的身份 |

请求头规则以官方 #117 合并提交 `1e6d69a3499ea67762289042aa84e22745f2cb27`
为参照：API 和 Provider 都不再主动过滤 `chatgpt-organization-id`、
`chatgpt-org-id`、`x-openai-organization`、`x-openai-project`。保留原始多值；
若字段被 `Connection` 声明为逐跳字段，仍不透传。HTTP 保留合法原始字节，
WS 保持已有的可序列化值规则。

这不等于放开所有组织与项目身份：`chatgpt-project-id`、`openai-organization`、
`openai-project` 仍与官方一样被过滤。认证、Cookie、账号和安装身份、响应方向脱敏、
State 注入、调度、连接池及指纹生成规则均不在本次调整范围内。

### 请求正文兼容收敛

后续正文对齐以官方 `f3236d041098bfa49698a95d3dc4b63174563181` 为固定基准：

- 字符串 `input` 在编码阶段转换成 user 消息数组，原始协议请求不变。
- `store` 只在缺少时补 `false`，显式值保留，内部续写判断与实际出站值一致。
- 只过滤 `max_output_tokens`、`temperature`、`prompt_cache_retention`；
  不再额外删除 `max_completion_tokens`、`top_p`、`frequency_penalty`、
  `presence_penalty`，也不再清洗输入条目 ID。上游仍可能拒绝不支持的值。
- 明确的 message/system 仍转换为 developer；工具关联、密文历史及未知内容保留。
- `client_metadata` 只主动补标准字段 `x-codex-installation-id`；
  已有 `installation_id`、`installationId` 继续同步为选定账号的设备号，
  缺少时不额外创建。不重新生成设备号，不修改身份、缓存或连接池编号算法。
- 保留同账号透传 metadata 的设备号同步，以及身份改写后的 ASCII JSON 编码。
  这两项分别防止旧设备号覆盖和 Unicode 内容造成 WS 请求头丢失。
- 设备编号的出站位置对齐官方 `0fba502`、`312059e`：Responses HTTP/WS 不主动
  添加独立设备头，也不透传下游同名头；设备号继续写入账号收敛后的正文及已有会话别名。
  复用现有同账号 metadata 修正，不叠加第二套处理。持久设备档案、生成规则、
  数据库锁、QX 会话/缓存派生、TLS 和 UA 均保持原样。

验证须覆盖缺省和显式 store 的续写分支、HTTP/WS 实际出站值、
缺失及已有设备别名、同账号连接复用、跨账号/Key 隔离、缓存和亲和依据。
本地或 Linux 回环测试不能代替真实上游接受度或缓存命中率验证。

成功记录和错误排查的“显示列”按钮分别管理本浏览器的偏好，可恢复默认；
账号、错误说明及操作等必要列不能关闭。既有账号表偏好不参与迁移。

后台任务与结果保存在当前进程中，不是跨进程的持久任务队列。刷新、关闭网页
不取消已接受任务；服务重启后任务记录不保留，已成功提交的账号仍在数据库。
结果不确定时先核对账号列表，不能因为任务消失就自动重放刷新令牌。

## 账号更新时间保护

账号记录更新时，`updated_at` 不早于原值和本次写入的观测时间，避免时钟回拨或
不同观测时间交错时，凭据刷新、手动换凭据、状态/额度更新被数据库时间约束拒绝。
版本冲突和旧观测拦截保持原样，不修改令牌到期、额度重置时间、设备身份或调度规则。
时钟回拨期间，显示的更新时间可能暂时不前进；不靠人为递增时间伪造新观测。
此修复不增加数据库查询，也不需要数据库迁移。
