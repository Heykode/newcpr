# IPv6 出口控制面

IPv6 出口默认保持原连接方式。新增地址默认禁用；只有显式启用的地址参与选择。
CPR 不修改操作系统接口、不自动安装地址，也不把地址清单或本机 socket 绑定成功称为互联网连通性验证。

## 管理入口

- Web：侧栏“IPv6 出口”维护本地源地址池与默认策略；“代理管理”维护转发代理，
  不是 IPv6 地址池入口。同一账号不能同时使用这两种出口策略。
- 账号：“编辑账号”内的 IPv6 策略经单独确认后立即提交，不随外层“取消”或关闭撤销，
  也不读取表单内未保存的代理更改。底部“保存账号设置”不提交 IPv6 项。
  可继承全局或显式“不启用 IPv6 策略”，后者保留原直连或代理设置。
- `GET /api/admin/ipv6-egress`：只读快照，包含版本、默认模式、地址池、
  全部现存 OpenAI 账号的覆盖项和已解析固定地址；读取不分配地址。
- `POST /api/admin/ipv6-egress/update`：`revision`、`defaultMode`、`addresses`；
  整体更新通过版本检查后在一个事务中提交。
- `POST /api/admin/ipv6-egress/account`：`accountId`、`revision`、`mode`；
  `mode` 缺失、为 `null` 或空字符串（含纯空白）代表继承，
  `"unchanged"` 为显式不启用 IPv6，不跟随全局启用。
- `POST /api/admin/ipv6-egress/expand`：`start`、`end`；仅展开有界地址范围，
  最多 4096 个，返回规范化的禁用地址，不保存、不探测网络。

以上端点均需要管理员认证。地址池总量最多 4096；拒绝 IPv4、IPv4 映射、
链路本地、站点本地、回环、未指定和组播地址。更新时仅校验启用地址能否在本机绑定。

## 模式与历史

支持 `unchanged`、`fixed_ipv6_reuse`、`random_ipv6_reuse`、
`fixed_ipv6_fresh`、`random_ipv6_fresh`。全局模式只作用于未覆盖的账号。
活跃 IPv6 模式与账号代理互斥，冲突写入整体回滚。

固定地址历史必须以完整的 Provider、上游账号 ID、上游用户 ID 关联，
不根据邮箱、昵称或本地账号 ID 猜测。地址池可用时，即使当前模式保持原连接方式或随机，
也可预分配固定地址，但预分配本身不会启用 IPv6。

新账号分配优先选择当前有效固定模式账号绑定数最少的地址；绑定数相同按地址列表顺序。
池用完后仍按最少绑定数选择并允许共享。历史身份优先恢复原地址，不重新均衡已有账号。
删除账号保留历史，但不继续占用空闲优先资格。重新导入相同完整身份恢复原地址，
不移动轮转游标。历史地址被禁用或移除后保留不可用状态，绝不悄悄改绑。
没有可用地址或上游身份未解析完整不阻止普通导入。

账户和配置变更提交后才发布新的 Provider 快照。模型请求直接读取内存快照，
不逐请求访问 PostgreSQL。新建连接策略不打断已经开始的响应，也不覆盖严格的
WebSocket 续接归属。复用 / 新建不是 HTTP/2 开关，不改变 WS / HTTP 协议选择；
每次独立连接只选择一次源地址，不逐帧轮换。连续会话优先原 WebSocket 连接。
