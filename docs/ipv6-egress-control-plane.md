# IPv6 出口控制面

IPv6 出口默认保持原连接方式。新增地址默认禁用；只有显式启用的地址参与选择。
CPR 不修改操作系统接口、不自动安装地址，也不把地址清单或本机 socket 绑定成功称为互联网连通性验证。

## 管理入口

- Web：侧栏“IPv6 出口”维护本地源地址池与默认策略；“代理管理”维护转发代理，
  不是 IPv6 地址池入口。同一账号不能同时使用这两种出口策略。
- 账号：“编辑账号”内的 IPv6 策略经单独确认后立即提交，不随外层“取消”或关闭撤销，
  也不读取表单内未保存的代理更改。底部“保存账号设置”不提交 IPv6 项。
  可继承全局或显式选择“默认 IPv4”，后者将普通直连限定为 IPv4，
  保留显式账号代理。State 探测的独立代理或 IPv6 出口不受影响。
- `GET /api/admin/ipv6-egress`：只读快照，包含版本、默认模式、地址池、
  全部现存 OpenAI 账号的覆盖项和已解析固定地址；读取不分配地址。
- `POST /api/admin/ipv6-egress/update`：`revision`、`defaultMode`、`addresses`；
  整体更新通过版本检查后在一个事务中提交。
- `POST /api/admin/ipv6-egress/account`：`accountId`、`revision`、`mode`；
  `mode` 缺失、为 `null` 或空字符串（含纯空白）代表继承，
  `"unchanged"` 为显式默认 IPv4，不跟随全局启用 IPv6；API 字段值保持兼容。
- `POST /api/admin/ipv6-egress/expand`：`start`、`end`；仅展开有界地址范围，
  最多 4096 个，返回规范化的禁用地址，不保存、不探测网络。
- 账号批量编辑：独立勾选“IPv6 出口策略”才提交；每次打开都默认不勾选。
  仅全部选中 OpenAI 账号时可用，不会静默跳过混选中的其他类型账号。
  `POST /api/admin/accounts/batch-update` 的 `egressMode` 省略表示不修改，
  显式 `null` 表示继承全局，五种字符串值与现有 IPv6 模式相同。
  与单账号独立保存接口不同，空字符串和 `inherit` 不属于合法 wire 值。
- 账号模板：`config.egressMode` 使用相同语义。“不修改”不写该字段，
  “继承全局”写 `null`。旧模板继续保持账号原有覆盖；模板应用以及使用模板
  创建的新账号都会落地所选模式。失效重登更新已有账号仍不套用新账号模板。
- 批量或模板应用按同一事务的最终代理和 IPv6 状态校验，可同时清除代理并启用
  IPv6。有账号代理冲突、账号不存在或类型不受支持时整批回滚，其他设置也不部分生效。

以上端点均需要管理员认证。地址池总量最多 4096；拒绝 IPv4、IPv4 映射、
链路本地、站点本地、回环、未指定和组播地址。更新时仅校验启用地址能否在本机绑定。

## 模式与历史

支持 `unchanged`、`fixed_ipv6_reuse`、`random_ipv6_reuse`、
`fixed_ipv6_fresh`、`random_ipv6_fresh`。全局模式只作用于未覆盖的账号。
活跃 IPv6 模式与账号代理互斥，冲突写入整体回滚。

界面中的“轮询 IPv6”保留 `random_ipv6_*` 存储值以兼容已有设置，但不再随机抽取。
同一个 CPR 进程的所有账号及两个轮询模式共用一个选址游标，按地址池顺序 A→B→C→A，
并发选址串行领取下一个地址，不使用账号独立游标。固定/默认模式不消耗这个游标。
跳过禁用与临时不可绑定的地址；只有一个可用地址时允许重复，全部处于冷却时保留既有
不可用错误。配置刷新保留最后选中地址的位置；该地址被移除时从新列表开头继续。
这是进程级轮询，不是跨服务器的分布式排队，也不限制同一 IP 的在途请求数量。

每个独立请求尝试选址一次，安全的 WS→HTTP 回退沿用该次选择；严格 WS 续接优先原连接，
不为每帧或连接内部重发重新选址。Excel HTTP/SSE 同样使用这个运行时与 IPv6 HTTP 连接池。
复用按账号、源 IPv6 和客户端配置隔离：切换到 B 不能复用 A 的 TCP 连接，轮回同一账号
的 A 时才可能命中仍有效的连接；其他账号不会因此共用该账号的连接池。

固定地址历史必须以完整的 Provider、上游账号 ID、上游用户 ID 关联，
不根据邮箱、昵称或本地账号 ID 猜测。地址池可用时，即使当前模式保持原连接方式或随机，
也可预分配固定地址，但预分配本身不会启用 IPv6。

新账号分配优先选择当前有效固定模式账号绑定数最少的地址；绑定数相同按地址列表顺序。
池用完后仍按最少绑定数选择并允许共享。历史身份优先恢复原地址，不重新均衡已有账号。
删除账号保留历史，但不继续占用空闲优先资格。重新导入相同完整身份恢复原地址，
不移动轮转游标。历史地址被禁用或移除后保留不可用状态，绝不悄悄改绑。
没有可用地址或上游身份未解析完整不阻止普通导入。

账户和配置变更提交后才发布新的 Provider 快照。模型请求直接读取内存快照，
不逐请求访问 PostgreSQL。新建连接策略不打断已经开始的响应，也不覆盖严格的
WebSocket 续接归属。复用 / 新建不是 HTTP/2 开关，不改变 WS / HTTP 协议选择；
每次独立连接只选择一次源地址，不逐帧轮换。连续会话优先原 WebSocket 连接。

## 连接池空闲回收

- 默认 HTTP 客户端显式设置 `pool_idle_timeout(None)`，不是忘记配置；连接池不按
  空闲秒数主动淘汰连接。上游关闭、网络断开、客户端被淘汰或服务重启仍会使连接失效。
- IPv6 源地址客户端设置 `pool_idle_timeout(60s)`。连接闲置后可被回收；正在发送、
  接收或流式返回的业务请求不因这项设置在第 60 秒被强制终止。
- 回收的是可复用的 HTTP 连接，不是账号、IPv6 地址或固定绑定。固定模式下一次请求
  仍使用该账号的历史地址重新建连；轮询模式继续领取全局下一个可用地址。
- 账号批量和模板设置仅复用原有控制面，不调整以上参数，也不改变 UA、身份指纹、
  Excel/Codex 链路选择、调度评分或严格 WS 续接规则。
