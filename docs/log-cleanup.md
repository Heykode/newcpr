# 日志清理

入口为系统设置的“日志清理”分区。仅管理员可读写，所有响应禁止缓存。
升级不会直接删除历史数据，自动清理默认关闭，需管理员保存后启用。

## 范围

| 类别 | 内容 | 初始保留 |
| --- | --- | --- |
| 请求日志 | `model_requests`、诊断轨迹、关联事件及过期无主运维事件 | 继承已有设置，至少31天 |
| 运行日志 | Host 配置目录中已完成压缩的三类 CPR `.log.gz` 分片 | 7天 |
| 错误采集 | 已完成、过期采集记录及对应本实例文件 | 继承采集设置，默认7天 |
| 管理员操作日志 | `admin_audit_events` | 继承已有设置，默认90天 |

请求日志删除会使对应历史明细及依赖明细的窗口统计不再可查。
账号、凭据、指纹、分组、路由、质量规则、余额、累计费用与扣费去重账本、
备份不在清理范围内。全局连续采集的旧完成记录可过期，采集任务本身继续运行。
正在执行的普通采集任务、正在写入的文件、符号链接和无关文件不删除。

## 执行

- 配置保留窗口与执行频率是两回事：每小时、每6小时或每日指定时区时间
  检查超期记录，绝非全量清空。每6小时按所选时区的0、6、12、18时执行。
- 手动清理须先保存配置，预览固定截止时间并确认。确认有效期10分钟，
  配置变化或已有任务时拒绝重复创建。
- 一个持久任务保存配置快照、截止时间及进度；数据库控制行锁保证实例间排他。
  每次数据库最多处理500条请求、500条无主事件或500条审计，短事务并限制等待。
- 文件任务属于接收任务的服务实例；运行 worker 无全局 leader 门槛，
  实例稳定标识复用采集目录标识。普通重启后继续；实例永久移除时可停止遗留任务后重建。
- 停止不撤销已完成的删除；关闭自动清理会终止自动任务，手动任务独立。
- 自动与手动执行共用同一实现。旧数据库 worker 已替换；采集后台仍执行
  到期停采与孤儿整理，但不自行删除超期记录。Host 日志仍轮转和压缩，
  不再根据 YAML 的旧保留字段自行淘汰，保留字段继续接受以兼容已有配置。
- 按批次记录进度。文件删除无法与数据库做跨资源事务，重启后重复处理是幂等的；
  极端中断时处理计数可能小于真实已删数量。失败不假报成功，其他类别可继续。
- `log_cleanup.*` 审计记录保留操作轨迹，不在页面提供历史结果列表。

## 占用

请求日志显示两张日志表的 `pg_total_relation_size` 之和，包含索引及 TOAST，
不再次重复累加。采集为元数据表加当前实例文件；运行日志为固定目录匹配文件。
Unix 文件用已分配块统计，数据库按 PostgreSQL 报告的文件大小统计。
页面使用十进制 KB/MB/GB；失败显示读取失败，只有实际测得0才显示0。
页面打开、手动刷新及观察到任务完成后重新测量；进度轮询不重新扫描文件目录。

数据库删除通常产生内部可复用空间，不保证立即归还系统。页面只显示实测
当前占用，不以删除条数估算释放空间，不自动执行 `VACUUM FULL` 或删除索引。
本功能不提供数据库物理压缩和部署备份清理。
