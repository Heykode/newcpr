# 凭证守护

参考 `ranxi2001/sub2api` v2.8.13 的 #71，在 CPR 管理端提供默认关闭的原生巡检。
它是独立运维功能，不要求开启 Excel。源码实现与测试进度不代表已部署。

## 工作方式

- `/token-guard` 设置开关、分组、模型、间隔、超时、并发和每轮账号数。
- 未选分组时覆盖全部 OpenAI OAuth 账号。优先处理最久未巡检的账号，
  每轮默认 12 个账号、6 并发、300 秒间隔，单个请求默认 60 秒超时。
- 复用账号管理的真实连接测试，发送 `Reply with one lowercase word: ok`。
  使用账号的既有路由、模型资格、并发限制、出口和身份配置；会消耗少量真实额度。
- 手动暂停、封禁、无效配置和额度耗尽的账号跳过，不主动解除限制。
  已失效凭据不重复生成请求。正常请求中持久化的凭据状态仍由 Provider 负责。
- 只有真实完成才记为可用；通用 401/403、模型无权限、网络错误或超时
  不直接推断账号已死或凭据失效。认证分类以 Provider 持久化的类型化事实为准。
- 账号凭据真正换代时丢弃旧巡检的观察；普通 Cookie 更新不误判换代。
  删除账号不恢复旧记录。关闭或保存设置取消旧轮未结束的探活。

## 重登

自动重登仍由“失效重登”的账号级自动开关、2FA 资料、工作区选择、重试预算和
原工作者负责。守护不会开启原本关闭的自动重登，不另建并发队列，不绕过 CAS、
人工暂停、封禁、额度限制和推送结果不确定保护。
页面手动重登也走相同目标确认和队列，成功凭据按原流程推送，不直接覆盖号池。

与参考项目的区别：当前使用 CPR 原生测试和既有重登，不内置或调用第三方
测活/重登站点，不提供该项目的外部接口、独立密码/2FA 表单、强制恢复调度开关
或独立 Bark 通道。这些并未作为完整移植交付；既有通知和失效重登设置保持原样。

## 记录与边界

最近巡检记录包含账号 ID、凭据版本、固定原因分类、耗时和时间，保留 14 天。
不存探活正文、上游原始错误、Token、密码或 2FA。配置保存进入管理审计。
后台 API 全部要求管理员认证，关闭开关不隐藏既有记录。

当前后台按本实例独立运行，没有新增跨实例巡检去重租约；多实例部署时应先补齐
该运行边界再启用，不把本实例并发上限理解为整个集群上限。
