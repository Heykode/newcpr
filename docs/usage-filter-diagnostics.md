# 请求筛选与错误排查

## 范围

本次只修改管理员观测查询和使用统计页面，不修改调度、指纹、账号凭据、
请求转发、重试策略或计费用量的事实口径。不执行服务器变更。

## 查询合同

- 共用筛选：账号多选、邮箱/名称/备注、Key、请求时的分组、时间、
  请求模型/上游模型、Excel/原生 Codex、上下游传输、状态码、IP、
  Request ID/上游请求 ID/Response ID、耗时和缓存。
- 搜索使用不区分大小写的字面子串；`%`、`_`、反斜线不充当 SQL 通配符。
  当前账号名称/备注和请求当时的邮箱/名称快照都能搜索；展示不改写历史快照。
- `/usage/account-options` 只返回最多 50 条非敏感账号标识。
  当前账号和指定时间内历史账号均可选，账号被删除后仍可按历史 ID 查记录。
  一次最多选择 50 个账号；名字相同的不同账号不会被合并。
- `route` 接受 `/v1/responses`、`/v1/chat/completions` 等精确端点，
  同时兼容旧 operation 查询。不能以内部 generate operation 区分 Chat 和 Responses。
- Response ID 保留原有不透明长标识合同，不套用普通筛选文本的 256 字符限制。
- 客户端状态码和上游状态码独立，两个都有值时取交集。
  运维事件没有独立客户端响应状态/上游传输，不借最终尝试的数据填补。
- 错误专用条件：分类、上游错误码、已记录的失败阶段、恢复状态和错误范围。
  阶段取同一次 attempt 的诊断证据；旧记录缺证据就不匹配。
- 默认错误范围仍包含请求错误和运维事件，保持旧接口行为。
  “请求最终错误”适合按逻辑请求排查，“各次尝试 / 运维事件”适合看重试。
  两者一起展示时不能把事件行数当作用户请求数。
- 成功列表继续只计成功且有用量证据的请求；错误专用条件不套进成功用量。
  列表、汇总和分析共用公共筛选及冻结的时间上界；翻页不滑动时间窗口。

## 页面生命周期

筛选保存在 URL 白名单参数中，刷新和返回可恢复。完整 `sk_` Key 不进入
查询或 URL，只保留已有的 10 字符可见前缀。无效数值/时间会提示并暂不应用。
修改有效筛选立即取消旧请求，重置分页，迟到响应不能覆盖新范围。

账号候选远程搜索，Key/分组复用现有只读列表接口；可按精确 ID 查历史记录。
点击表格里的账号或请求模型可继续下钻，不改变账号配置。

## 与详细采集并存

另一个分支的 `b28d9385` / `cf0aebac` 提供全局详细错误采集。
本分支不实现第二套采集开关，也不改其存储、容量、保留时间和迁移。

共同编辑点只有 `frontend/src/views/usage/index.vue`：
保留请求明细标题旁的 `DetailedCaptureControl`，统一筛选位于页面上方。
`RequestDiagnosticsPanel` 继续拥有选中的 Request ID，
`RequestCaptureDetails` 按该 ID 懒加载；筛选列表不得预取正文。

组合验证在临时副本中三方合并前端，原两个工作树均不互相覆盖。
合并发布时必须同时保留上述入口及新的筛选组件，不能用整文件覆盖解决冲突。
