# 账号月度成本与保本价

## 页面与口径

账号列表在“优先级”右侧显示“保本价”：

**保本价 = 每账号人民币月成本 / 本周期已确认的美元消费金额**。

单位为“元／美元额度”，不是同币种倍率，不涉及汇率换算。比如月成本 50 元、
本期消费 200 美元，保本价为 0.25 元／美元。没有设置成本或本期没有消费时显示横线；
明确填 0 表示免费账号，有消费时显示 0。单元格仅显示数值或横线；成本、累计消费、
周期、单位与历史完整性说明均放在鼠标悬停提示中。

金额沿用 CPR 既有累计消费的成功交付、已知费用和币种判断。它不是官方额度百分比，
也不新增收费或影响 API Key 计费、定价、模型限制、调度、指纹、UA、代理或出口。
原生 Codex 与 Excel 的已确认美元消费都按现有口径入账，未知费用不猜测为零。

## 设置方式

- 导入账号：可选填写每账号月成本，同一批每个账号使用该价格，不按账号数平摊。
  不填表示保留已存在的成本；新账号则不设置。
- 单个编辑：可设置或修改成本，清空金额表示移除成本设置。
- 批量编辑：先勾选“修改所选账号成本”；未勾选时不修改成本。
  勾选后留空会清除所选账号成本。每次重新打开对话框都需要重新勾选。
- “续费起算日”首次留空默认为上海日期的今天；已有周期留空则保留。
  修改价格本身不重置消费；修改起算日只调整统计范围，不删除账目。

按起算日的月度周年周期自动计算，不是每周额度窗口，也不是向前滚动 30 天。
月末仅钳位到当月最后一天，不逐月漂移：1 月 31 日 → 2 月 28 日 → 3 月 31 日。
周期结束不包含结束日，费用归属按请求开始时间转换为上海日期。新周期自动沿用同一价格，
不产生实际付款或续费操作。页面沿用现有账号列表刷新机制，不新增上游额度轮询。

## 身份与账本

稳定身份使用 `provider_kind + upstream_user_id + upstream_account_id`（工作区），
不使用邮箱、Token 或本地账号行 ID 猜测同一账号。身份未确认时拒绝设置成本；
待身份确认后可从编辑入口补设。

同一稳定身份重新授权、重登、重复导入、删除后重新添加，继续使用同一成本账本。
换到另一工作区不会串账；每次新请求尝试记录所选账号时保存身份快照，
同一次尝试的终态写入保留原快照，新重试则按新尝试的账号重新快照。
周额度刷新、改价格、清理请求日志不会清零已经入账的消费。旧周期记录继续保留，
但不会计入本周期分母。

`0057_account_purchase_costs.sql` 新增持久身份、账号映射、每日消费三张表以及请求身份快照。
复用既有 `account_cumulative_cost_entries.request_id` 去重，在同一事务累计每日费用；
不改变原长期累计消费表按本地账号 ID 统计的语义。
所有金额以 PostgreSQL 精确十进制计算，前端仅格式化显示。

## 旧数据与升级

只有同时保有时间与身份依据的历史费用才能回填。已经清理的请求日志没有日期证据，
不能从永久累计总额反推某个月的消费。已轮换凭据的账号，早于最近账号更新时间的旧日志
没有可靠工作区快照，不归入当前工作区。相关周期的悬停提示标记“历史记录不完整”，只使用可核实消费，
不能理解为完整历史的准确保本价。缺失发生时间之后的新完整周期不再显示该警示。

本功能包含数据库迁移，不属于无迁移快速发布；后续部署应使用经过审核的迁移发布流程。
已发布迁移不可修改，不能直接切换到缺少此迁移的旧二进制。普通账号删除和日志保留任务
不得删除成本账本或请求去重记录。
