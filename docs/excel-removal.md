# BPS Excel 链路移除

## 当前边界

本变更移除 BPS Excel 的执行链路和管理入口。它不会恢复已经退役的旧 State 功能。
历史设计见 `excel-upstream.md`；历史设计中的启用、恢复、图片中转步骤不再适用于本版本。

| 删除项 | 保留与核对范围 |
| --- | --- |
| Excel 请求转换、工具包装、SSE、压缩、图片上传和中转 | 原生 Codex Responses、Chat、Messages、Compact、图片生成/编辑 |
| Excel 回放仓库、暂停恢复 worker、专属探测 | 原生续接、会话粘性、交付索引、额度恢复、质检与保活 |
| BPS 专属代理池与预热 | Codex 的 Mihomo/代理池、租约、评分、冷却、预热、IPv6 出口 |
| 添加/编辑/批量账号、重登、模板中的 Excel 控件与提交字段 | 身份、凭据、2FA、代理、模型权限、分组、权重、并发、购入成本 |
| Excel 设置页、图片策略和专属 API 装配 | 通用设置、重试、队列、Fast/Ultra Fast、计费、国家策略 |
| 质检 `enable_excel` 与原生恢复后关闭 Excel 动作 | 暂停、移组、应用普通模板、阈值、自动恢复及并发修改保护 |
| Excel 提交前缓冲与定时器 | 原生前导事件即时交付、输出后的重放禁止、首包统计、原始 wire |

不按关键词批量删除：`multiplier_bps` 是计费基点；Mihomo `BPS-<port>` 是共享监听器名称；
`excelFailureThreshold` / `excel_streak` 已被普通模板和暂停/移组逻辑复用，继续保留。

## 旧配置清理

迁移 `0105_retire_excel_configuration.sql` 精确删除账号模板及已知嵌套配置中的退役字段，
保留模板 ID、名称、版本、引用和普通设置。含普通配置的模板不会整份删除。
读取旧模板时同样丢弃这些明确列出的字段；未知字段仍严格拒绝。

- 清理账号模板、质检规则/模板/组规则及重登入池计划中的已知 Excel 字段。
- 旧 `enable_excel` 动作变为 `none`，仅清理该动作的专属恢复计数。
- 普通质检的模板所有权和共用阈值不会清空。历史所有权快照只忽略退役字段，
  普通配置的比较、身份、版本及手动修改保护继续生效。
- 清理专属图片运行参数、Excel 恢复任务与槽位，删除两个专属恢复触发器。
- 不修改账号路由、身份、凭据、出口、分组或并发配置，不修改历史使用日志及质检结果。
- 历史质检详情按当时记录返回已知动作和模板字段；可执行规则单独解析，同一旧动作在活动规则中只能变为“不处理”。历史列表不加载配置快照。
- 保留历史迁移、旧列/表和历史传输标识的读取兼容。旧 Excel 会话不能静默转换到 Codex 续接。
- 历史独立暂停不会被自动解除；用户明确手动启用账号时仍沿用原有解除暂停标记的行为。
- 不清空共享 Redis；已经无人写入的 Excel 回放缓存等待原有 TTL 到期。

迁移与清理仅在部署升级时作用于实际数据库。本地修改和隔离验证不表示线上已经清理。
本轮没有部署授权；未来发布需按数据库迁移部署流程审核，不能使用无迁移快速切换。

## 原生性能与验证要求

保留账号请求配额、WebSocket 每账号建连配额及建好/失败/取消时的释放行为、连接复用和回收。
原生流不增加缓冲、等待、锁或后台查询。旧 `streamPrefetchBytes` 暂留配置读取兼容，
已没有请求运行时消费者，也没有界面控件；它不会改变原生交付。

验证必须在指定隔离验证主机完成：全工作区编译、前端类型/lint/构建、共享单元和浏览器回归、
真实 PostgreSQL/Redis 回归、迁移前后数据及引用比较、HTTP SSE/WS 首事件和吞吐对照。
不能把缺少连接参数而跳过的存储测试、只检查转换文件或整套测试总耗时当作验证通过。

## 隔离性能对照

基线为 `930bd92c3a1a49a6b65e2a389eb5db21f668bae2`，候选为本次完整移除结果。
两版独立编译并核对生产源码摘要，使用同一个临时测试函数；测试代码不进入发布源码。
相同验证主机、Rust 工具链、镜像、CPU/内存上限，测试按 A/B、B/A、A/B 串行交替，
测量期间不并行运行本任务的编译、浏览器和其他重负载回归。

每版每轮包括 HTTP SSE / WebSocket 与 1 KiB / 257 KiB 前导事件四种组合；
每组合 128 次请求，舍弃前 8 次热身，保留 120 次样本。后续输出固定为 128 × 512 字节。
下表单位为毫秒，格式为“基线 → 候选（变化）”；各数值是三轮各自百分位的中位数，
不是合并所有样本后的百分位。第一组未固定 CPU，第二组固定相同的两个逻辑 CPU。

这组测试使用未优化的测试构建和 loopback 上游，并为每次请求新建测试 Provider 与连接。
首事件包含请求准备与建连，后续数据耗时衡量固定输出的读取交付；不能用其百分比
推算真实上游首 token、生产连接复用吞吐或并发容量。

### 小包首事件分段诊断

为区分请求准备、建连与首事件交付，追加相同的分段计时临时测试。
两版各三轮，每轮 528 次请求、舍弃 16 次热身；每版共 1,536 个有效样本。
仍使用相同两个逻辑 CPU 和串行 A/B 顺序，各轮 CPU 配额节流计数均为零。
交付计时从合成上游开始发送前导事件起，包含 loopback 传输、解码和网关输出。
分段计时构建与前两组不同，两组原始结果保留，不能混合计算同一个百分位。

## 独立复查

- 旧管理页能把退役字段和普通并发设置一起批量提交。复查在隔离主机复现了整批被拒；
  修复后只忽略八个已知字段，只发退役字段没有可用操作，陌生字段仍拒绝。
- 真实 PostgreSQL 复现历史详情与已保存的动作不一致：旧规则的 `enable_excel` 在详情被误报为 `none`。
  修复后，历史动作和模板快照只在管理员详情回显，活动规则仍为 `none`。
  新旧两种快照均校验已知字段；无法识别的嵌套恢复字段不会原样对外返回。
- 设置页删除没有控件的缓冲输入模型，普通设置保存经回归确认不会覆盖旧缓冲值。
  删除了运行设置写入命令中的 Excel 默认模型和新审计事件的对应标签，保留数据库原值与历史审计。
- 对照核查了原生选号、队列、图片路径判断、出站和交付。另在隔离主机复跑
  WebSocket 池内部及传输回归 72 项、真实 Redis 队列回归 32 项、真实 PostgreSQL 质检回归 51 项。
  本次复查的修复只涉及管理端，不改原生连接池、重试和输出路径；上面的性能数据来自先前的原生链路对照。

## 提交后复查

- 用隔离账号复现了两处管理界面误报：留有旧路由标记的账号能看到不可用的模型目录导出，
  也能尝试开启后端不执行的自动重置。账号列表、详情和额度刷新现在按实际账号返回能力。
  原生 Codex 仍可使用这两项；旧策略可以手动关闭，不恢复任何 Excel 配置。
- 节点间模型可用性报告原先漏读了旧账号的有效模型列表，会把实际无法选用的模型报为可用。
  现在只排除该账号原来走退役路由的模型；同一账号的其他原生模型不受影响。
  这些修正不参与请求转发，也不增加数据库查询。
- 桌面与手机浏览器复查涵盖账号菜单、单编/批编、导入、2FA、重登、模板、质检、
  运行设置、两个 Codex 代理池与历史用量筛选，同时核对普通设置的提交参数。
  旧记录仍可按 Excel 筛选，活动表单不提供此选项。
- 单独对照移除前后两个版本的模型白名单弹窗：清理最后一个缺失模型后，
  两版都能保存并重新读取正确的名单；键盘焦点均未回到刷新按钮。
  模型目录说明的 Escape 检查也在两版中出现过同时关闭编辑弹窗的情况。
  两项均保留为原有界面问题，本次不修改通用弹窗或模型限制逻辑。
