# 分组预警界面合同

## 1. 范围

设置页通知渠道和账号管理分组预警独立于运行参数、账号设置。复用现有
BaseModal、BaseSwitch、BaseNumberInput、BaseSelect、BaseToast 和主题。

## 2. 入口

- `NotificationChannelsCard.vue` 位于现有设置页，根节点 `notifications`。
- `GroupAlertSettingsModal.vue` 从分组卡片右上角 Settings 进入，位于 Pin 左边。
- `api/modules/notifications.ts` 统一渠道、策略、测试和投递记录接口。

## 3. 交互合同

- 全局、SMTP、Bark 三层默认收起，各自记忆展开状态；凭据不得存 localStorage。
- 根摘要显示配置和最近测试结果/时间；`#notifications` 链接展开根区域。
- 测试先保存当前草稿，保存失败不发送。SMTP 无账号认证时仍可配置成功。
- 分组默认关闭；四个条件、确认时间、收件人、Bark 样式分别配置。
- Bark 等级、铃声、音量、持续响铃支持继承全局；布尔覆盖使用三态选择，
  不用两态开关抹掉继承状态。
- 只读 `updatedAt` 从策略写请求剔除；渠道写请求剔除 `lastTest`。
- 加载失败禁止保存/测试，不能把初始默认值覆盖到服务器。
- 切换分组或关闭弹窗使旧读取失效；保存响应只更新原来对应的分组。
- 开关 `label` 只作为无障碍名称，必要的可见标签必须另行渲染。
- `activeAlerts` 只改变设置图标颜色，不增加卡片高度或额外轮询。

## 4. 校验与失败

空测试邮箱在前端拒绝。后端错误可见且保留草稿。测试发送失败也重读最近
结果。保持同一动作单次在途；不要自动重复未知结果的发送请求。

测试前保存失败时，不得重新加载服务器配置或清空任一渠道的草稿及凭据输入；
只有保存成功后才刷新测试结果。失败后必须解除忙碌状态，允许用户修改并重试。

## 5. 例子

正常：Bark 重要警告可覆盖音量为 8，关掉自定义音量恢复全局继承。
普通：全局 SMTP 不填用户名密码也能用可信无认证中继。
错误：策略读取 503 后仍允许点击保存，将已有配置覆盖成默认关闭。

## 6. 测试

运行通知 API 和分组监控测试、总览 SSR 回归及浏览器交互测试。浏览器在
1440/390/320px、深浅色检查折叠、表单、保存、测试成功/失败、无溢出。
测试只能拦截合成数据；截图、日志在仓库外保存。

## 7. 错误与正确写法

错误：`data: policy` 把 GET 返回的 `updatedAt` 原样交给严格写 DTO。

正确：构造写入字段并移除只读字段，API 测试断言请求中不存在 `updatedAt`。
