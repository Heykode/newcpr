# 原生错误保护、WS 生命周期与负载统计

## 1. 适用范围

适用于官方 #537、#547、#548 迁入后的 NewCPR 原生实现。
本规范补充既有协议、调度、额度、质量检测和身份合同，不引入插件执行器。

## 2. 接口与归属

- `requestTuning.accountErrorProtection` 经 Admin 配置、Core 编译策略、Store
  发布 Redis 策略；`ProviderStream` 对每次业务尝试反馈一次。
- `AccountProtectionGuard` 包含凭据修订、策略代次、重置代次和证据版本。
  `AccountProtectionState` 只保存到期时间、规则标识和恢复要求，不存错误正文。
- `register_downstream(key, cancellation)` 登记真实下游连接生命周期。
  `has_downstream_binding` 是换绑清理的依据；仅有非空连接标识不构成登记。
- `usage_concurrency(range, filter)` 查询现有 `model_requests`，贯穿 Admin、API
  和前端 `performance.load`，不新增或改写 SQL 迁移。

## 3. 行为合同

- 错误保护默认 `enabled=false`、`rules=[]`；阈值 12、窗口 600 秒、保护
  7200 秒、恢复探测开启。只有管理员配置有效规则并启用后才累计。
- 同一失败命中多条规则仍只计一次。没有上游错误事实的本地失败不计；
  完整成功才清零，取消和提前断流不能作为成功。质量检测、诊断不累计。
- 保护状态独立于额度冷却、模型限制和人工暂停；恢复保护不能解除这些状态。
  探测型保护到期仍阻止普通调度，探测成功才解除，失败按保护时长延后。
- 无关设置更新保留计数；凭据更新、手动恢复和策略修改阻止旧反馈改写新状态。
  关闭后停止新计数，已有保护到期解除。默认关闭且无遗留保护时选号不增加 Redis 读取。
- 上游 WS 每 25 秒主动 Ping，首次延后一个间隔，背压时暂停且恢复后跳过错过的 tick。
  Ping/Pong 写入最多 5 秒，不设 Pong deadline；心跳不刷新业务空闲或池回收时间。
  未绑定的闲置连接 300 秒回收；
  已绑定且下游存活的连接不因闲置回收，但仍遵循最大年龄和账号物理容量。
- 下游心跳独立于业务写入：25 秒发送，首次未确认 Ping 后 30 秒无入站活动
  判定超时；重复 Ping 不能延后此期限，写心跳等待最多 5 秒。
- 收包活动依据底层真实字节读取更新，不必等完整 WS 消息解码。持续慢上传
  不误断；半帧停止上传且不回应心跳时仍关闭。保留 Axum 升级校验、原有
  owner、取消与租约释放，不能用无限延长心跳取代真实收包进度。
- 真实下游换绑时清理其旧链；精确续接转移物理连接所有权，旧下游取消不能
  关闭新所有者。没有生命周期登记的 lane 保留原有连接和续接归属。
- 关闭中的连接、代理许可和账号物理容量直到 socket 实际销毁才释放。
  旧 `ResponseControl` 的等待必须结束并释放接收锁，不能抢占新所有者。
- 并发以请求生命周期事件扫描，包含跨时间桶和运行中业务请求；过滤与原统计
  一致。负载图增加平均/峰值并发和等待 P95，保留原调度图的容量 P95、覆盖率。

## 4. 验证与错误矩阵

| 场景 | 必须结果 |
| --- | --- |
| 保护关闭或规则未命中 | 原请求执行结果保持不变 |
| 上游失败命中多规则 | 单次反馈，不重复累计 |
| 到期探测失败或取消 | 不恢复调度，不解除额度冷却 |
| 凭据更新后旧请求返回 | 不重新冻结或恢复新凭据 |
| lane 标识相同但没有生命周期登记 | 不凭此关闭旧 UA/凭据/线程连接 |
| 两个 lane 各有连接，再精确续接其中之一 | 不覆盖另一连接，不无限等待 |
| 已登记连接换绑或关闭 | 清理对应旧链，物理容量不能提前释放 |
| 下游心跳无回应但持续重复发送 | 仍按首次未确认期限结束 |
| 上游不回复 Pong / 持续回复 Pong 但业务停滞 | 前者不增加断开期限，后者仍按业务空闲期限结束 |
| 一条大消息连续慢上传 / 半帧停传 | 前者不误断，后者按原心跳回收 |
| 跨桶请求、质量探测、未来时间段 | 分别正确计入、排除、停止增长 |

## 5. 正常、基础与错误示例

正常：管理员配置 `code=busy` 后累计连续匹配失败，恢复探测成功仅解除错误保护。
基础：未启用保护的请求继续沿用原选号、身份、重试和结算。
错误：把所有 429 都改成该保护，或把仅带 lane 标识的请求当成真实下游生命周期。

## 6. 必须测试

- Core 验证匹配、单次反馈、成功/取消边界和关闭旁路。
- 隔离 PostgreSQL/Redis 验证设置保留、原子计数、凭据/策略栅栏、到期领取、
  过期索引及恢复不清除额度冷却；测试账号必须使用有效 `acct_` ID。
- Provider 回环测试保留旧 UA/凭据的精确续接、不同线程和 Key 的身份隔离，
  并测试已登记换绑、无登记 lane 冲突、Close 超时和真实物理容量释放。
  改变上游心跳后必须回查所有维护/GC/lazy-start 测试服务端：回应 Ping 并继续等待
  Close，保留原关闭期限；不得把“第一帧必须是 Close”误作生命周期合同。
- API 覆盖 Pong、持续业务入站、无回应超时、阻塞写、断开结算和单次错误转发。
- 浏览器覆盖保护保存/重载/规则编辑、账号状态及桌面/手机两种统计视图。

## 7. 错误做法与正确做法

错误：`downstream_connection_id != ""` 就回收所有同标识 socket。

正确：先核对 `has_downstream_binding`；无生命周期登记时仍按既有 lane 和
精确响应 ID 归属复用，真实下游才转移绑定和清理旧链。

错误：保护恢复调用通用账号解禁，或把关闭按钮直接当成清空所有冷却。

正确：只修改独立保护状态，保留额度、模型、人工启停及凭据修订边界。
