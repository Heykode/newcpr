# 日志清理合同

- `0056_log_cleanup.sql` 只添加控制记录，不删除历史数据；初始自动关闭。
- 管理入口经 AdminAuth、固定类别和校验用例，不接受任意表名/SQL/路径。
- `PgLogCleanupStore` 使用控制行锁、固定截止时间及任务配置快照。
  `run_batch` 每次短事务，删除上限、SQL超时、锁超时独立生效；错误保存后处理下一类别。
- retention 以长驻任务连续处理手动和定时清理；有进展时仅让出执行机会，不设每秒条数、批次间睡眠或整个任务超时。500条请求/审计、100个文件/采集仅为事务/操作边界。
- 启动、配置、取消事务提交后通知本实例后台；2秒轮询仅用于空闲时发现到期任务及外部状态变化，不限制运行中任务。数据库异常交给现有监督器退避，锁竞争或无进展批次才等待后重试。
- `SKIP LOCKED` 的短批次不等于完成；请求、孤立事件、审计在短批次后检查匹配行是否仍存在。锁超时 `55P03` 回滚本批并保留类别，不误标失败或跳过记录。无删除且未完成的批次必须退避，防止忙循环。
- 服务停止时完成当前有界批次及进度提交再退出，避免文件已删除而进度保存被取消；管理员取消仍以持久化任务状态为权威，每批重新读取。同实例重启仍按原截止时间/配置快照续跑。
- 正常业务请求没有额外清理查询；管理进度与磁盘占用分开读取。
- 请求终态及 completed_at 决定过期；FK级联运维事件必须向用户披露。
  账号、额度、累计计费/扣费去重记录不纳入清理。
- Host 只删固定目录内三种前缀的已归档 `.log.gz`，检查文件日期与修改时间。
  不跟随符号链接，不碰当前 `.log`、临时归档和其他项目文件。
- 日志文件测试按部署时区计算文件日期，复用 `deployment_today()`；不能用UTC日期拼部署时区文件名，否则跨日时会虚报文件不存在。
- CaptureManager 继续停采过期任务、整理孤儿文件，不单独按天删除历史。
  统一清理在 IO 互斥下处理已完成记录；全局连续采集可逐记录过期。
- 详细采集 `quotaPolicy` 缺省 `stop`；`overwrite` 先完成一个有界的新文件，再在同一
  CaptureManager IO 互斥下按 `created_at,id` 淘汰最旧采集记录，不能先删历史再发现新条过大。
  单条超限跳过且继续采集；配置配额为已保存逻辑字节，临时文件最多额外一条且不超过 128 MiB。
- `/request-captures/clear` 只接受管理员确认和固定截止时间，每批最多 256 条。仅删除
  本实例索引关联的 UUID 普通采集文件和对应记录，拒绝链接/异常文件；不删任务、使用明细、
  普通错误、金额、账号或其他实例内容。删除前验证所有目标，提交采集索引删除和审计后移除文件；
  文件移除失败按存储异常停采，残留孤儿文件由原有机制处理，不谎报成功。
- 完整手动清理后，仅在全局开关已开启、无存储故障、已有容量时恢复暂停的全局采集；
  不开启已关闭的配置、不复活限时任务。清理期间新增材料不进入原截止时间的后续批次。
- `runtime_settings` 的请求/审计保留和采集配置的保留字段为兼容数据源，
  新页面保存与审计同事务；配置版本推进后现有快照缓存可刷新。
- 清理配置的保留天数允许为 `0`，表示清理截止时刻之前全部已结束历史；请求中的运行记录、活动日志文件和运行中的采集任务仍保留。
- `0` 不写入旧版 `runtime_settings` 的窗口字段，也不把全局统计窗口改成零；它只控制日志清理和详细采集清理。
- 请求清理的 `1..30` 天也由 `log_cleanup_control` 独立保存和读取，不写入至少31天的旧统计窗口。不得仅修复写入而在读取时又用旧窗口覆盖短期限；31天及以上仍保留旧客户端兼容同步。
- 页面天数输入最低1天，各类别通过独立“全部清理”复选框表达历史API的0值；勾选时禁用天数输入，取消恢复正数。旧0值加载为已勾选，确认弹窗明确展示全清与按天保留。
- 回归必须使用真实隔离PostgreSQL覆盖0/1/3/4/30/31/45天保存回读、短期限手动与定时执行、近期及运行中请求保护；只测试0天不足以证明1至30天可用。
- 数据库字节使用 `pg_total_relation_size`，含TOAST/索引不重复相加。
  文件Unix按分配块统计；读取失败保留未知，不伪造0。
- 不自动执行物理缩库。页面不展示历史清理结果，只更新当前占用。
- 真实测试库需显式 `CPR_TEST_DATABASE_URL` 和 `CI=true`，不能将跳过当通过。
- 清理运行器的暂停时钟/取消回归保留在 `worker.rs` 的私有 `cfg(test)` 内联模块；架构审核只允许精确拥有者和模块名，不导出测试专用生产接口。新增测试须同时跑 gateway 架构检查及工作区测试，不能以 store 专项代替。
- 新增数据库表时，同步 `connect_and_migrate_should_apply_all_migrations_once_and_reopen_cleanly`
  的精确表清单并实测生产迁移入口；专项清理测试不能代替迁移回归。
- 前端格式检查覆盖完整目录，包括浏览器测试 HTML；仅检查 TS/Vue 不足以覆盖 CI。
