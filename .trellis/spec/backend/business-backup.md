# 业务备份合同

## 1. 范围

v3.29.6 选择性适配：业务归档省略诊断历史，保留账号、身份、出口、账务及全局小时用量。
不引入插件统计投影，不修改在线日志清理或每请求账务写入。

## 2. 接口

- `PgDumpAdapter::new(staging, database_url, database_password, pool)`。
- `BusinessSnapshot::begin(pool)` 使用只读可重复读事务和导出的 PostgreSQL 快照。
- 迁移 `0076_backup_usage_hours.sql`：`bucket_start` 主键，`counts`/`costs` JSON 对象。
- 新对象 `.sql.gz`；下载名按对象格式区分旧 `.dump`。

## 3. 合同

- pg_dump 与小时统计使用同一快照；流式压缩，限制和摘要针对压缩字节。
- 排除请求明细、错误事件、审计和采集索引；保留累计消费、幂等账本与 Key 预算。
- 全局基线只用于空过滤条件。不能虚构账号、Key 或模型归属。
- 只汇总已结束业务请求，使用原有完整交付用量口径，排除已恢复中间失败。
- 恢复后新请求与旧基线合并；再次备份不能重复累计。
- 小时内精度、明细、尝试数、延迟和计费覆盖率不可恢复，必须在文档说明。
- 新库恢复只删除空 schema，不使用 CASCADE 自动覆盖已有业务。
- 旧完整暂存继续上传；尚未导出的旧格式任务失败并提示重新创建。

## 4. 验证矩阵

| 情况 | 结果 |
| --- | --- |
| 导出失败、取消、超时 | 结束子进程，删除部分归档 |
| 压缩后超限 | staging_space_exhausted |
| 全局查询 | 实时数据加恢复基线 |
| 按账号筛选 | 只返回存在的明细 |
| 二次备份恢复 | 基线加新请求各计一次 |

## 5. 场景

正常：恢复业务归档后累计账务与预算不变，明细为空，全局用量仍可读取。
基准：未恢复过的实例基线表为空，原有统计语义不变。
错误：清理明细时删除累计账务，或者把小时汇总伪造成账号请求。

## 6. 测试

隔离数据库真实 pg_dump/gzip/psql 两轮恢复；核对身份、账本、预算、全局统计、
首页趋势及筛选隔离。测试样本遵循全部迁移后的账务结构，不沿用初始迁移的旧字段。
覆盖新旧下载、遗留队列、取消、压缩限制与清理；新迁移加入冻结清单。

## 7. 错误与正确

错误：直接搬官方插件统计表，或恢复后用假账号承载历史。
正确：使用 NewCPR 独立恢复基线，明确全局小时精度和明细不可恢复的边界。
