# 分组监控通知合同

## 1. 范围

通知仅消费已有十秒分组监控样本。不得调用上游额度刷新、修改账号状态、
调度、指纹、估值、并发准入或账号列表刷新周期。采样先保存，告警评估
最多等待三秒，失败不影响监控读取和健康状态。

## 2. 接口和存储

- `GET /api/admin/notifications/channels`
- `POST /api/admin/notifications/channels/update`
- `POST /api/admin/notifications/test`
- `GET /api/admin/notifications/deliveries?groupId=...`
- `GET /api/admin/account-groups/alert-policy?groupId=...`
- `POST /api/admin/account-groups/alert-policy/update`

全部要求管理员认证。渠道更新仅接受 `smtp`、`bark`；策略更新不得提交
只读 `updatedAt`。数据库迁移 `0037_group_monitor_alerts.sql` 新增渠道、
策略、事件、投递队列四张表。配置写入和管理审计使用同一事务。

迁移 `0095_group_bark_schedules.sql` 增加每组 `bark_schedule_json`、outbox 的
`incident_activated_at` 和 `bark_rule_key`，以及当前事件查找索引。旧投递的
事件时间从 `created_at` 回填；创建时间不再兼作事件身份。不得改写旧迁移。

## 3. 数据合同

- SMTP 密码和 Bark Device Key 只写，空字符串保持原值。读取和 Debug
  不暴露密钥。`passwordSet/deviceKeySet` 由服务器现有值或真实新密钥决定，
  不信任客户端标记。数据库遵循项目既有凭据存储方式，未新增应用层加密。
- 并发使用 `usedSlots / totalSlots`，默认 90%，持续 20 秒。
- ETA 仅使用 `ready` 且有限的分钟值，默认不超过 10 分钟，持续 30 秒。
- 额度为零和可调度账号为零默认立即触发。删除最后一个账号仍可触发。
- 未知数据通过 `enabled=true,current_value=None` 显式传给 Store，不触发告警，
  并打断未完成的确认与整组恢复计时。禁用条件不阻止恢复。
  预计过期额度从不触发告警。
- 每组每条件保留确认记录，同组按一轮连续异常对每个邮箱去重。Bark 同轮
  只在提醒强度高于已经成功发送的最强提醒时补发。
  所有启用条件明确正常连续 30 秒，才一起清除激活记录并重新允许通知。
  任一条件异常或未知都取消整组恢复；缺失历史条件的部分样本不能证明恢复。
- 十秒采样相邻有效观察间隔超过 15 秒时，重置未完成的确认或恢复计时。
  已激活的事件继续保留，不能因漏采样、重启或未知数据重新发送。
- 按固定分组顺序锁已有 `account_groups` 行，再读取、更新条件事件及入队，
  保证不同条件同时首次触发也只产生每目标一条通知。拒绝旧采样覆盖新状态。
- 邮件只在条件首次确认时检查目标去重。Bark 为支持时段进入与升级，在已确认且
  当前仍异常的样本上评估；用当前组、条件及 `incident_activated_at` 索引查询
  当前事件投递，不扫描全量历史。未知数据不产生新的补发。
- Bark 默认时区 `Asia/Shanghai`、默认提醒开启、时段列表为空，保留旧行为。
  每组最多 24 条有序时段；严格 HH:mm、起止不同，支持跨午夜，开始包含、结束
  不包含。第一条启用且命中的规则优先，未命中使用默认提醒；默认关闭则不投递。
  四种条件的阈值和确认时间沿用该分组设置。免打扰不清除持续异常及恢复状态。
- 时段等级、铃声、音量、持续响铃可继承本组默认，本组默认再继承全局。
  规则指纹包含 ID 和解析后的样式；强度沿用 Tools：等级顺序 passive、active、
  timeSensitive、critical，等级权重 100，加音量，再加持续响铃的 20。
- 同组正在发送的 Bark 阻止并发新投递；当前规则 pending 复用原行重试，耗尽五次
  后同一规则不重新无限入队。过时 pending 标记 cancelled；未发送的 cancelled
  不算已通知，时段再次命中时允许重新入队。发送前重查时段和解析后的规则指纹，
  不匹配直接取消，不调用传输。已发送的同级/降级通知不重复。
- 每个收件人和 Bark 各一条 outbox；五分钟回收失联 claim，失败一分钟后
  独立重试，最多五次。旧事件恢复后停止未发送的旧通知。
- 测试通知原子插入为 `sending`，直接发送自己的 ID，失败不重试，也不创建事件。
  分组 Bark 测试按当前时段解析样式；免打扰时明确拒绝，不入队、不发送。
  入队后若规则变化，发送前取消并返回错误，不能向界面报告测试成功。
- 传输有界：SMTP 总超时 20 秒；Bark 10 秒且响应最多 16 KiB，禁止重定向。
  Bark POST 使用服务地址下的 `/push`，不把密钥拼到 URL。
- 对端已收到但本地未成功落库的异常中断仍可能重发，不能承诺跨 SMTP/Bark
  的严格 exactly-once。

## 4. 校验与错误

| 输入或状态 | 行为 |
| --- | --- |
| 非管理员 | 401 |
| 未知请求字段 | 422 |
| 非法端口、音量、阈值、邮箱、Bark URL | 400 |
| SMTP/Bark 未启用或没有真实配置 | 不创建可投递事件 |
| 发送失败 | 固定分类文案及数字状态码，不回传上游响应正文、URL 或凭据 |
| 分组策略或渠道关闭 | 发送前复查，不继续实际投递 |
| 时区、时段、重复 ID 或超过 24 条 | 400；嵌套未知字段或未知等级为 422 |
| 旧客户端未提交 barkSchedule | API 保留该组已有时段配置 |
| 投递前时段不匹配 | cancelled；不记为成功或传输重试失败 |

保存和投递共用 `normalized_bark_device_key`：容忍外围空白与尾斜杠，
拒绝完整链接、内部路径和非法字符。投递时也规范化已保存的旧密钥，但不回写配置。
SMTP 密码不裁剪，不要求登录账号与发件地址相同。SMTP 认证、超时、TLS、
连接及拒收错误，Bark HTTP、业务返回码、超时及响应格式错误分别使用安全枚举。
投递记录保存该枚举转换后的安全消息，禁止直接格式化传输库异常或对端文本。

展示用 `refreshing` 或含 `pending_group_ids` 的监控结果不得参与告警确认或恢复。

## 5. 正常与异常例子

- 并发 95% 持续 20 秒产生一次邮件和一次 Bark，之后 95% 不再产生新通知。
- 短暂超过阈值后恢复，重新开始计时，不累计不连续的异常时段。
- 邮件成功、Bark 失败，仅重试 Bark。
- 时间不足告警后，即使接着出现并发不足、额度归零，也不重复发送同轮提醒。
- 正常 20 秒、未知 10 秒、再正常 10 秒不算连续正常 30 秒。
- 没有任何通知路由时不激活事件，之后配置路由仍能正常首次告警。

## 6. 验收

真实隔离 PostgreSQL 覆盖迁移、秘密字段、策略保存、多实例首次激活、
重复采样、恢复、旧采样、分目标重试和测试通知。API 覆盖认证、严格 DTO、
伪造密钥标记和全局投递读取。Host 使用本地模拟 SMTP/Bark，禁止真实凭据。
前端测试位于 `group-monitor-alerts.test.mjs` 和 `browser/group-alerts.mjs`。
追加验证跨午夜边界、重叠顺序、DST 重复时刻、分组独立保存、静默转提醒、
并发升级去重、取消后重新进入时段、失败重试上限，以及旧数据库的投递回填。
Admin 阈值测试使用 `tests/use_case/notifications.rs` 中的公开服务入口，Host
传输测试使用 `tests/notifications.rs` 中的 `HostBundle::notification_delivery`。
不得在生产 `src` 内增加测试模块或为测试开放私有接口；必须运行网关应用的
跨工作区架构检查，不能仅验证 Admin、Store、API、Host 包。

## 7. 错误与正确写法

错误：对不存在的事件 `SELECT FOR UPDATE` 后直接入队；多个实例都认为首次激活。

正确：先 `INSERT ... ON CONFLICT DO NOTHING` 固定主键，再锁同一行，状态和
outbox 同事务提交。失败后的状态更新必须包含配置读取和配置校验失败路径。
